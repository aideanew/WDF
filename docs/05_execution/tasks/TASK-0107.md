## 归属切片

## 来源需求
MUST-05、MUST-07、03 §3.4.1 第 6/7 条

## 来源方案
`contracts/save`（`SavePushReq/Res`、`SavePullRes`）、`save_snapshot` 表

## 目标
客户端能把存档推到服务器，服务器按 `baseRevision` 判定接受或冲突，并保证同一 `rid` 只生效一次。

## 输入
- 契约：`packages/contracts/src/save/index.ts`
- 表：`save_snapshot`（`player_id` PK、`revision`、`checksum`、`body`）
- 前置：AT-0104（鉴权就绪）、本地 PostgreSQL 已建表

## 输出路径
- `server/src/modules/save/**`
- `server/src/gateway/handlers.ts`（把 `save.pull` / `save.push` 从 `todo` 换成真实实现）

## 执行步骤
1. `save.push`：读 `baseRevision` ↔ 库中 `revision`：
   - 相等 → 写新行（`revision+1`），返回 `{accepted:true, revision}`；
   - 不等 → **不报错**，返回 `{accepted:false, conflict:{revision,savedAt,schemaVersion,level}}`。
2. `checksum` 与 `body` 的校验：服务端**不复算**业务逻辑（本阶段），只存；但必须校验 `checksum` 字段存在且为整数。
3. 幂等：`(player_id, rid)` 命中 `idempotency` → 直接回放首次响应。
4. `save.pull`：返回 `summary` + `snapshot`（无档时 `summary=null`）。
5. 事务：写 `save_snapshot` 与写 `idempotency` 必须在**同一事务**内。

## 验收标准
1. 首次 push（`baseRevision=0`）→ `accepted:true, revision=1`；
2. 并发两客户端都用 `baseRevision=1` → 一个成功、一个拿到 `conflict`（**不是 500**）；
3. 同 `rid` 重复 push → 只写一次，第二次回放首次响应；
4. `save.pull` 能取回与 push 完全一致的 `body`。
