## 目标
把"先剥离旧 checksum 再封印"这条铁律变成**会红的测试**：任何未来把 `sealSave({...带 checksum 的对象})` 写回去的改动，测试必须失败。

## 输入
- 代码：`packages/game-core/src/save/schema.ts`（`sealSave/verifySave/computeChecksum`）
- 参照实现：`client/assets/scripts/services/save/LocalSave.ts:57-62`（正确做法：先解构掉 `checksum`）、`HookModel.applyToSave`（同模式）
- 前置状态：`tests/determinism/game-core.test.mjs` 已有基础用例；本任务为**新增独立文件**

## 输出
- `tests/determinism/save-seal.test.mjs`（新增）

## Execution Steps
1. [ ] 用例 1：`sealSave(body)` → `JSON.parse(JSON.stringify(...))`（模拟落盘/读盘）→ `verifySave` 为 `true`
2. [ ] 用例 2（反例）：构造 `sealed = sealSave(body)`，再 `sealSave({...sealed})` → `verifySave` 为 **`false`**（证明"不剥离就必坏"）
3. [ ] 用例 3（正确路径）：`const {checksum: _stale, ...rest} = sealed; sealSave(rest)` → `verifySave` 为 `true`
4. [ ] 用例 4：改 `body.modules` 任一字段后不重封印 → `verifySave` 为 `false`（篡改必被发现）
5. [ ] 用例 5：`checksum` 为非整数（如字符串）→ `verifySave` 为 `false` 且不抛异常

## 验收标准
