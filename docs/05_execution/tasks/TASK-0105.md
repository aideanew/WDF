## 归属切片
S1（AT-0105）

## 来源需求
MUST-10（配置热更）、MUST-16（合规）、MUST-09（客户端版本闸）

## 来源方案
`contracts/compliance`（`ComplianceRes`）、`contracts/config`（`ConfigManifestRes`）、`config_release` 表

## 目标
让启动链的第 1、2 步返回真实数据：合规状态 + 当前 `configVersion` + 最低客户端版本。

## 输入
- 契约：`packages/contracts/src/compliance/index.ts`、`config/index.ts`
- 表：`config_release(version, min_client, pack_url, released_at)`
- 数值：`npm run gen` 产出的 `configVersion`（当前 `16921d30a67a934f`）
- 前置：AT-0104（鉴权）

## 输出路径
- `server/src/modules/compliance/**`
- `server/src/modules/config/**`
- `server/src/gateway/handlers.ts`（替换 `compliance.check`、`config.manifest` 两项）

## 执行步骤
1. `config.manifest`：从 `config_release` 取 `active` 记录（**注意 D-05：当前表无状态字段，先取 `released_at` 最大的一条**），返回 `{configVersion, packUrl, minClientVersion}`。
2. `compliance.check`：返回 `{verified, minor, playableUntil?, offlineAllowanceMs}`；本阶段 `verified=true`、`minor=false`（**真实实名链路在 AT-1003**），`offlineAllowanceMs=0`（ADR-0008 必须联网）。
3. 版本闸：请求 `m.cv` < `minClientVersion` → 返回 `9001 CLIENT_TOO_OLD`（在 `rpc.ts` 统一拦截，不只在这两个动作里）。
4. **不得**伪造实名结果；接口未接通前必须在响应里带明确标记（如 `verified` 语义为"免实名开发态"）。

## 验收标准
1. 返回的 `configVersion` 与 `npm run gen` 输出**完全一致**；
2. `packUrl` 为空时不报错（返回 `undefined`）；
3. 构造 `cv` 低于下限 → 返回 `c=9001`；
4. `npm run verify` 通过。

**两条实现口径（原卡未写明，这里定死）**：
1. 版本闸**只在登记过 `config_release` 记录时生效**。本地开发无发布记录 → 不拦任何请求（落实"先本地开发，不用真机和认证备案"）。
2. `config.manifest` **豁免**版本闸。否则旧客户端拿不到"该升到哪一版、包在哪"，形成永久自锁。见 [KB-FIX-20261023-06](../../08_knowledge/technical-notes/fixes/FIX-20261023-06-version-gate-deadlock.md)。

**证据**：[EVD-0105](../../06_validation/evidence/EVD-0105/README.md)（4 条验收标准逐条对应 + 版本闸三段边界）
