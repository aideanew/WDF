## 目标
把 34 张只有 `id,name,note` 的表，按设计文档补出**可用的列结构**（schema + CSV 表头），使生成物与读取方能按字段工作；**只补结构，不填没有出处的数字**。

## 输入
- 34 张占位表（CSV 仅 13 字节表头的）：
  `ad_placements, bait, blueprints, buildings, consumers, crew_traits, defenses, events, event_drops, explore, facilities, fish, foods, generators, guide_steps, hooks, islands, limits, lines, merchants, oil, phrases, protection_cards, quality, regions, rooms, seasons, shipwrecks, spawns, throwables, titles, unlocks, waves, zones`
- 对应 `game-data/schemas/<表>.schema.json`（当前 `fields` 只有 id/name/note）
- 设计原文：v5.5 第十一~十三章、`材料与工具总表.md` 各节

## 输出路径
- `game-data/schemas/<表>.schema.json`（34 个）
- `game-data/source/<表>.csv`（34 个表头）
- `docs/04_planning/plan-v001/02-requirements-baseline.md` §3.4（追加缺失项）

## 执行步骤
1. 逐表建立**字段来源表**（放证据目录）：`表.字段 ← 文档名 + 章节 + 原文摘句`。**没有出处的字段不加。**
2. 命名与类型统一：字段名 `snake_case`；类型只用 `string|int|number|bool`；主键沿用 `id`。
3. 先改 `schema.json` 的 `fields`，再把同样的列写进 CSV 表头（两者必须一致；顺序一致）。
4. `todo` 字段处理：该表所有字段都有出处 → 删掉 `todo`；仍有字段缺出处 → 保留 `todo` 并写清缺哪个字段。
5. 设计文档里**只有描述、没有数值**的列（如 weight/capacity/stack/size）→ **只加列、不加行**，并在证据里登记为待补（N-1/N-2 已在册，不重复造号）。
6. 每完成一批（建议按"材料/设施/生物/活动"分组）跑一次 `npm run gen` + `npm run verify`。

## 验收标准
1. 34 个 schema 与 34 个 CSV 表头**字段名、顺序、类型**完全一致；
2. 证据目录有"逐字段出处表"，每个字段都能指到文档章节；
3. 没有任何字段或数值是"凭感觉加的"（抽查 3 个字段必须能定位原文）；
4. `npm run verify` 全绿（含生成物未被手改）。
