## 目标
运维（当前就是用户本人）能用**一条命令开新区**、**一条命令封号**；新玩家落在当前开放区；被封玩家登录被拒且留审计记录。**不建任何管理后台界面，不新增玩家可调用的管理动作。**

## 输入
- `server/db/migrations/0001_init.sql`（已执行）
- `game-data/source/regions.csv`（区服 id/name 来源；**空表时不得自编区名**，先登记未知）
- `server/src/modules/ops/`（已存在，当前为占位）

## 输出路径
- `server/db/migrations/0002_regions.sql`
- `server/src/modules/ops/open-region.mjs`、`server/src/modules/ops/ban-player.mjs`（CLI，直接连库执行）
- `server/src/modules/account/**`（登录时校验 `banned_until`）

## 执行步骤
1. `0002_regions.sql`：建 `regions(id text PRIMARY KEY, name text NOT NULL, status text NOT NULL DEFAULT 'open', opened_at timestamptz NOT NULL DEFAULT now(), is_current boolean NOT NULL DEFAULT false)`；给 `player.region` 建索引；**保证全表最多一行为 `is_current=true`**（唯一部分索引或触发器二选一，写清理由）。
2. `open-region.mjs`：入参 region id/name → 插入 `regions` → 事务内置 `is_current`（旧的置 false）→ 写 `audit_log`（`actor='ops'`, `action='open_region'`）。
3. `ban-player.mjs`：入参 playerId + 截止时间 → 更新 `player.banned_until` → 写 `audit_log`（`action='ban_player'`）。
4. `account.login`：若 `banned_until > now()` → 拒绝登录。**错误码只能用现有码**；若无合适码 → 登记到未知登记册并**停下问用户**，不得自造数字。
5. 记录上线操作手册到 `docs/07_release/`（一段大白话：怎么开区、怎么封号、怎么回滚）。

## 验收标准
1. 执行 `open-region` 后：`regions` 新增一行且 `is_current` 唯一；
2. 新注册玩家 `player.region` = 当前区；
3. 执行 `ban-player` 后：该玩家登录被拒，`audit_log` 有两条以上记录；
4. 仓库内**没有**任何管理后台页面/管理动作接口；
5. `npm run verify` 全绿。

## P6 补验（2026-10-29，FIX-27 / FIX-29）

**FIX-27（P0）**：规划者复核发现 `account.refresh`（`handlers.ts:38`）只验签名、从不查 `banned_until`，令牌 TTL 2h 但 refresh 不计次不失效 → 不停 refresh 封号永远不生效（「能力已实现、调用点没接」）。修复：
- `service.ts`：把 `login` 的封号判断抽成共享 `activeBanUntil`（**不复制第二份**）+ 新增 `assertNotBanned`。
- `handlers.ts`：`account.refresh` 在 `refreshClaims` 成功后、`issueToken` **之前**调 `assertNotBanned`；判定用 handler 注入的 `t`，不用 `Date.now()`。
- 突变验证：删掉 `assertNotBanned` 调用 → **AT-1401-5 红**（`0 !== 2003`）；复原 → 7/7 绿。证明该调用是封号生效的 **load-bearing** 约束。

**`assertNotBanned` 必须 3 参 `(playerId, plat, nowMs)`**：审计要求 `actor = plat`（写 `audit_log(actor=plat, action='refresh_banned')`），2 参签名写不出正确操作者（写 `'system'` 即造假审计）。这是满足「审计留真实操作者」的**唯一正确解**，**不许后人「简化」回 2 参**（若简化，须连同审计口径一并改，且需规划者裁决）。

**FIX-29**：`openRegion` 的 `ON CONFLICT (id) DO UPDATE` 去掉 `opened_at = now()`（开区时间只写一次，重开不重写）；新增 **AT-1401-7** 验证重开 `opened_at` 不变、`is_current` 仍唯一。
