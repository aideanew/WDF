## 来源方案
`材料与工具总表.md` 第十五章「每日一海」第 8 条（计分口径）、第 6 条（场内出箱与锁档）、第 7 条（箱内物品）；
契约 `packages/contracts/src/event/index.ts`（`EventOp` / `EventSubmitReq` / `EventSubmitRes`）。

## 目标
服务端拿到客户端提交的 `EventOp[]` 后，用**同一随机种子 + 同一规则**复算总价值，产出 `EventSubmitRes.totalValue` 与物品清单；客户端上报的分数**一律不采信**。

## 输入
- AT-0801 产出的场次（`event_session` 行含 `seed`、`loadout`、`ops`）
- `game-core` 现有原子规则（hook / chest / economy）
- `prices.csv`（物品原价，来自 AT-1501）

## 输出路径
- `packages/game-core/src/event/**`（复算规则，纯函数、无 IO）
- `server/src/modules/event/**`（`event.submit` 真实实现）
- `packages/contracts/src/event/index.ts`（**仅当**现有类型不足，且须先获用户批准）

## 执行步骤
1. 在 `game-core/event` 写 `replayOps(seed, loadout, ops) → { totalValue, items }`：固定种子驱动箱子生成（`场次模式` = 每钩必中 + 锁档 不上锁 50% / 铁 25% / 铜 15% / 银 9.8% / 金 0.2%）。
2. 计分：**打开的箱子本身原价 + 带走物品原价**；卸下的锁不计分；未打开箱子不计分（原文第 4、8 条）。
3. `event.submit`：读 `event_session` → 校验 `ops` 序列合法（时间单调、动作在 3 分钟内）→ 复算 → 写 `total_value`；不写 `settled_at`（结算归 AT-0803）。
4. 幂等：同一 `sessionId` 重复提交返回首次结果（沿用 `rid` 机制，不新增表）。
5. 生成器带 `mode: 'daily' | 'event'` 开关：日常走 0.001%–2% 出箱率，场次走每钩必中（U-05 已定 A）。

## 验收标准
1. 同 `seed` + 同 `ops` → 两次复算结果完全一致（确定性单测）；
2. 篡改客户端 `totalValue` 不影响服务端结果；
3. 箱子本身按表价计入总分；`prices.csv` 无价的物品 → 记 0 并登记未知（不自编）；
4. `npm run verify` 全绿。
