## 目标

## 执行步骤
1. 造数：构造 500 个独立玩家会话（令牌），得分值分布接近真实（长尾）。
2. 压测参数（三条必须**同时**满足才算达标）：
   - 同时在线 **500 人**；
   - 排行榜**读 200 QPS、写 100 QPS**；
   - 上述两类请求 **P99 ≤ 200 毫秒**、错误率 **< 0.1%**。
3. 单次压测时长建议 ≥ 10 分钟（覆盖一次快照刷新），记录 P50/P95/P99、错误率、CPU、内存、连接数、慢查询。
4. 判定：
   - 三条全过 → **不加 Redis**，在 ADR-0004 记"达标（日期 + 数据）"。
   - 任一不过 → **先加索引、改查询**（记录改了什么）→ **再测一次**。
   - 仍不过 → **才加 Redis**，再测，门槛不变。
5. **不得**在未做第 4 步前直接引入 Redis；**不得**通过降低门槛来"达标"。

## 验收标准
1. `EVD-0903/` 内有原始压测输出（时间、并发、QPS、P99、错误率、机器指标）；
2. ADR-0004 有明确结论：达标不加 Redis / 不达标且已按顺序处理；
3. 若加了 Redis，ADR-0004 记录前后两轮数据。
