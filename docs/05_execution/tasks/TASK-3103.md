## 归属
- 所属切片：S-PLAY
- 来源需求：MUST-09（合成）；**等级门槛不实现**——`recipes.unlock_level` 0/79 填充，UI 必须显式标注"暂不设等级门槛"，不得假装有门槛
- 来源方案：`recipes.csv` 80 行已转录；`TASK-3201` 的 `canCraft/consume`

## 目标
合成 Tab 列出配方，按"材料够 / 不够"分色；点制作扣材料写本地存档，revision+1、checksum 有效。

## 输入
- 契约：`packages/game-core/src/crafting` 的 `RecipeShape/canCraft/consume`（TASK-3201 产出）
- 数据：`recipes.csv`（80 行）+ `items.csv`（106 行，用于显示名称）
- 前置任务：TASK-3101、TASK-3201
- 前置状态：`LocalSave.save()` 已修 checksum 缺陷（10-26）

## 输出
- `client/assets/scripts/features/crafting/model/CraftingModel.ts`（实现）
- `client/assets/scripts/features/crafting/view/CraftingPanel.ts`（实现 TASK-3101 的桩）

## Execution Steps
1. [ ] `CraftingModel.recipes()`：从 config 读 80 条 `RecipesRow`，映射为 `RecipeShape`
2. [ ] `CraftingModel.canCraft(recipeId)`：读当前库存 → 调 game-core `canCraft`，返回 `{ok, missing}`
3. [ ] `craft(recipeId)`：`canCraft` 通过 → `consume` → 写回 `modules.inventory`（扁平 map `{ [itemId]: number }`，**无 `.items` 子键**）→ `LocalSave.save()`；失败返回 `UxView`
4. [ ] Panel：列表按 `ok` 分两组（可制作 / 材料不足），不足项显示缺什么（`id 名称 ×缺口`）
5. [ ] UI 顶部固定一行说明："当前版本不校验等级与职业（数值未定）"，避免误认为功能完整
6. [ ] 埋点：`craft.success{recipeId}` / `craft.fail{recipeId,missingCount}`

## 验收标准
- [ ] 库存给 `木板×20`（或任一配方真实输入）→ 对应配方变为"可制作"，其余保持"材料不足"，数字与 `recipes.csv` 一致（人工抽 3 条）
- [ ] 点制作后：库存减少、产物 +1、`revision` +1、`verifySave` 通过
- [ ] 不满足的配方点制作无副作用（库存与 revision 均不变）
- [ ] 界面明确显示"不校验等级与职业"提示
- [ ] 客户端类型检查通过；守卫 9/9
