## 目标
新增 `toUxState(code)`：14 个错误码一一映射到 6 个界面态；`conflict` 只能由业务字段产生，不得由错误码产生。

## 输入
- 文档：`docs/03_solution/design/DESIGN-0001-ux-states.md` §2 映射表
- 契约：`common/errors.ts`（`ERR` 14 码）、`save/index.ts`（`SavePushRes`）
- 前置任务：无
- 前置状态：`npm run verify` 全绿（实测 9 守卫 + 65 测试，2026-10-26）

## 输出
- `packages/contracts/src/common/ux.ts`（新增）
- `packages/contracts/src/common/index.ts`（追加 re-export）
- `tests/contract/ux.test.mjs`（新增）

## Execution Steps
1. [ ] 定义 `export type UxState = 'loading' | 'empty' | 'error' | 'noPermission' | 'success' | 'conflict'`
2. [ ] 定义 `export interface UxView { state: UxState; code?: number; retryable: boolean; next?: 'login' | 'update' | 'wait' | 'contact' | 'tomorrow' | 'retry' }`
3. [ ] 用 `Record<number, Omit<UxView,'code'>> satisfies Record<(typeof ERR)[keyof typeof ERR], ...>` 写全量映射表（14 条，数值照 DESIGN-0001 §2，**不得自行调整**）
4. [ ] 实现 `toUxState(code: number): UxView`：`code === 0` → `{state:'success',retryable:false}`；未知码 → 落到 `4999` 同款（`error`/`retryable:true`），并在注释里写明"服务端新增码未同步"的处置
5. [ ] 实现 `conflictOf(res: SavePushRes): boolean`（`accepted === false`）
6. [ ] `npm run sync` 生成客户端副本，确认 `client/assets/scripts/generated/contracts/common/ux.ts` 存在且带 GEN_HEADER

## 验收标准
- [ ] 遍历 `Object.values(ERR)`，每个码都有映射，且 `retryable` 与 DESIGN-0001 §2 逐行一致（测试断言，不靠人眼）
- [ ] `toUxState(0).state === 'success'`；`toUxState(3002).state === 'empty'`；`toUxState(2003).state === 'noPermission'`；`toUxState(4001).retryable === true`
- [ ] `conflictOf({accepted:false,conflict:{...}})` 为 `true`；`conflictOf({accepted:true,revision:1})` 为 `false`
- [ ] 不存在把 `3001` 映射成 `conflict` 的代码路径（测试断言 `toUxState(3001).state === 'success'`）
- [ ] `packages/contracts/tsconfig.json` 类型检查无错；守卫 9/9 不回归
