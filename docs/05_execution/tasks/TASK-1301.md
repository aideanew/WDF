## 目标
玩家获得称号后，能在**排行榜行**与自己信息区看到称号文字；无称号时不显示、不报错、不占位。

## 输入
- `game-data/source/titles.csv`（当前只有 `id,name,note`；列结构由 TASK-1503 补齐）
- S9 的 `leaderboard.query`（返回 `RankRow[]`，含可选 `title`）
- `player` 表已有；`title_award` 表**不存在**，需本卡新增迁移

## 输出路径
- `server/db/migrations/0003_title_award.sql`（**新编号，不得与 0002 冲突**）
- `server/src/modules/leaderboard/**`（`query` 填 `title` 字段）
- `client/assets/scripts/features/leaderboard/view/**`（榜单行渲染称号）

## 执行步骤
1. 新增迁移 `0003_title_award.sql`：
   `title_award(player_id text NOT NULL REFERENCES player(id), title_id text NOT NULL, awarded_at timestamptz NOT NULL DEFAULT now(), source text NOT NULL, PRIMARY KEY (player_id, title_id))`。
2. 服务端 `leaderboard.query`：对返回的每一行补 `title`——取该玩家**最近一条** `title_award`；查不到则**不填该字段**（保持 `undefined`，不要填空串）。
3. 客户端榜单行：有 `title` 才渲染，样式与字号从 `b-common` 现有 UI 资源取；无 `title` 时行高不变。
4. **发放逻辑不在本卡**（归结算/活动）；本卡只做"读 + 展示"，不做任何 write 动作。

## 验收标准
1. 手工插入一条 `title_award` 记录 → `leaderboard.query` 返回该行带 `title`；
2. 客户端榜单能看到称号文字；移除记录后不显示且无报错；
3. `npm run verify` 全绿（迁移文件被守卫接受、生成物未手改）。
