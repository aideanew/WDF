## 目标
设置页"云存档"区可手动同步；`save.push` 返回 `accepted:false` 时弹二选一，选择后调用 `resolveFork` 并刷新到收敛后的存档。

## 输入
- 契约：`packages/contracts/src/save/index.ts`（`SavePushRes`/`SavePullRes`/`ResolveForkReq`）
- 前置任务：TASK-3101（面板桩）
- 前置状态：`LocalSave` 可用；服务端三方动作已实现

## 输出
- `client/assets/scripts/features/settings/model/SaveSyncModel.ts`（新增）
- `client/assets/scripts/features/settings/view/SettingsPanel.ts`（实现 TASK-3101 的桩 + 云存档区）

## Execution Steps
1. [ ] `SaveSyncModel.status()`：`save.pull` → 返回 `{localRevision, cloud: SaveSummary | null}`
2. [ ] `push()`：`save.push{baseRevision: local.revision, snapshot: local, checksum}` → `accepted:true` 记为 `success`；`accepted:false` → 置 `conflict` 态（携带 `conflict: SaveSummary`）
3. [ ] `resolve(keep)`：调 `save.resolveFork{keep, localSnapshot: keep==='local' ? local : undefined}` → 成功后重新 `pull` 并覆盖本地（`keep==='cloud'` 时必须整档替换，不能只改 revision）
4. [ ] UI：显示"本地 rev N / 云端 rev M"；冲突弹窗两按钮分别说明后果（"保留本地将覆盖云端/保留云端将丢弃本地进度"）
5. [ ] **禁止**把 `3001 DUPLICATE_REQUEST` 当冲突（DESIGN-0001 §5）——`3001` 走 `toUxState` → `success`，直接刷新状态
6. [ ] 埋点：`save.conflict` / `save.resolve{keep}`

## 验收标准
- [ ] 制造分叉（本地改内容且 `revision` 落后于云端）→ push 后出现冲突弹窗，两个按钮文案明确
- [ ] 选"保留本地" → 云端 `revision` = 本地 +1；再 pull 得本地内容
- [ ] 选"保留云端" → 本地被整档覆盖，`verifySave` 通过（checksum 有效）
- [ ] 同 `rid` 重复 push（模拟网络重试）→ 不产生第二次冲突、不重复写库
- [ ] 客户端类型检查通过；守卫 9/9
