## 输入
- `game-data/source/drops.csv` 现有列：`id,group,item,min,max,weight_bp`（当前仅表头，0 行）
- 已可转录的事实（原文照抄）：
  | 锁档（`group`） | 件数 `min`–`max` | 品阶分布 |

  | 不上锁 | 1–3 | 白 70% / 绿 30% |
  | 铁锁 | 2–4 | 白 35% / 绿 50% / 蓝 15% |
  | 铜锁 | 3–5 | 绿 35% / 蓝 50% / 紫 15% |
  | 银锁 | 3–6 | 蓝 35% / 紫 50% / 金 15% |
  | 金锁 | 4–8 | 紫 60% / 金 40% |
- 补充约束（原文）：内容以原料、基础材料、珍宝、种子、图纸为主；可打造成品最多占 10%；开锁工具按已定掉落表另算；锁开下来也算一件。

## 执行步骤
1. 按上表逐锁档转录：件数写 `min`/`max`；品阶分布写进 `weight_bp`（把 % 换算为万分比整数，如 70% = 7000，**换算不改语义**）。
2. `group` 取值用锁档标识（与 `locks.csv` 的 id 对齐；`locks.csv` 若仍为空，先用锁档英文标识并在此卡证据里写明）。
3. **停下列清单**：设计只给了"品阶 + 品类倾向"，**没有给"某品阶下具体有哪些 item"** → 该缺口登记为 **N-11**，写入未知登记册；**不得**用 `items.csv` 现成 id 自行拼一套掉率。
4. 若 `drops.csv` 的 `item` 列无法表达"品阶"，**不要改列**：把方案（加 `tier` 列 vs 用 `item` 存品阶）写进证据，**停下问用户**。
5. 跑 `npm run gen`，确认生成物更新且未被守卫拦下。

## 验收标准
1. `drops.csv` 至少有 5 个锁档、每档件数区间与文档逐字一致；
2. 品阶权重换算正确（每档合计 = 10000 bp）；
3. 未知登记册有 N-11（品阶→具体 item 映射缺失），且**没有**任何自编 item 清单；
4. `npm run verify` 全绿。
