## 来源需求
MUST-06（必须联网）、03 §3.4.2（错误码 → 前端展示）、03 §3.4.6 界面 1

## 来源方案
`contracts/common/envelope.ts`（封套）、`platform/contracts/IPlatform.ts`（request）、03 §3.4.2 表

## 目标
把"启动 → 合规 → 登录 → 拉配置 → 进入游戏"这条 7 步链跑通，并让所有后端错误都有中文可读提示。

## 输入
- 契约：`RpcRequest` / `RpcResponse` / `ERR`
- 前置：AT-0101（工程与 Boot 场景）、AT-0104（登录）、AT-0105（compliance/config）、AT-0106（本地存档）

## 输出路径
- `client/assets/scripts/app/BootController.ts`
- `client/assets/scripts/services/net/**`（`RpcClient`）
- `client/assets/scripts/services/log/**`（错误上报占位）

## 执行步骤
1. `RpcClient`：封装 `POST /v1/rpc`；自动注入 `m = {rid?, cv, cfg, sv, plat}`；`auth=true` 的动作自动带 token。
2. 统一解析：`c===0` 返回 `d`；否则按 03 §3.4.2 表把 `c` 映射成 `{title, message, retryable}` 并 toast。
3. `BootController` 按序执行：`compliance.check` → `config.manifest`（比对 `configVersion`）→ `account.login` → `save.pull` → 进入主界面；每步失败按 6 态规范展示。
4. 断网检测：`onNetworkChange` 为断开 → 顶部横幅"已断网（只读）"，所有写操作按钮置灰。
5. **不实现任何玩法**；S1 阶段"出一钩"用临时直线实现（S2 替换）。

## 验收标准
1. 12-first-cut §12.5 的 7 步脚本全部走通；
2. 故意改错动作名 → 界面出现可读错误（不是空白/卡死）；
3. 断网 → 横幅出现，按钮置灰，不产生"假成功"；
4. 无 `wx.` 出现在 `features/`（`npm run guard` 通过）。
