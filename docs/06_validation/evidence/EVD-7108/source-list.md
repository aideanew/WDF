## 二、两个用户裁决点

### 裁决点 P1：units 3 兵种具体是谁

- **已定**（U-02，设计要点记录.md:747）：v1.0 三个兵种 = 近战、远程、坦克各 1，每类取**解锁等级最低**的那个。
- **无源**：设计源**没有给兵种解锁等级**（DS §7.2:517 数值待定），故无法判定 9 兵种里哪些属于近战/远程/坦克类、更无法判"每类解锁最低"。
- **卡升级条件**（PD7-08）：`若 3 兵种的选取需要重新裁决（设计源没写"哪 3 个"）→ 升 opus + 请用户定`。
- **建议**：请用户在 9 兵种里指定近战/远程/坦克各 1。候选（按 §7.2:510 清单语义推断）：
  - 近战：盾牌手 / 重甲兵 / 轻步兵
  - 远程：弓箭兵 / 弓弩兵
  - 坦克：重骑兵 / 轻骑兵 / 器械兵 / 蛙人潜水兵
  （分类本身设计源也未明确，需用户一并确认。）

### 裁决点 P2：waves 波次（BLOCKED）

- **已定**：野人袭击=塔防+回放、玩家不在线自动结算、无预警（DS §7.1:494-495）。
- **无源**：设计源**没有"第几波来几个敌人、波次间隔"数值**。§7.1:491 只给"窝点每周刷新、1-2 个、规模随岛等级增长"；§7.2:348 只给"第一波调成一座箭塔+一颗烟雾必胜"（定性）。
- **卡阻塞条件**：`设计源没有"波次"数值 → waves 留空 + BLOCKED 上报（没有波次就没有塔防，不许自己编）`。
- **结论**：waves 表**留空**，PD7-08 **部分 BLOCKED**（waves 无法转录）。其余表（units/defenses/throwables/islands/protection_cards）仍可先做结构部分。
