# 经验教训

（按日期追加）

## 2026-10-23

1. **生成器只能删自己产出的文件。** `client/assets/scripts/generated/` 里同时躺着工具产出的 `.ts` 和 Cocos 产出的 `.meta`；整目录 `rm -rf` 会静默改掉资源 uuid，表现为场景里 `Missing Script`。清理必须按"上次产出清单"逐个删，且按后缀白名单（只删 `.ts`）。→ KB-FIX-20261023-01
2. **"verify 全绿"必须先确认它真的跑完了。** 中途抛错也会打出前几步的 ✅，只看最后几行容易误判。判定标准是退出码 + 最后一行"全部守卫通过"。
3. **文档里的"事实基线"有保质期。** plan-v001/01 写"`.meta` 为 0"，几小时后就被 S0 推翻。任何基于旧快照的结论，动手前必须重新实测一遍再引用。
4. **"新增一个目录"也是变更。** 根目录白名单同时存在于 `tools/guard/checks.mjs` 与 `GOV-0002` 两处，只改一处就会红；新建根级目录（`.workbuddy`、`.vscode` 等）必须两处同改。→ KB-FIX-20261023-02
5. **编辑器里填了不等于存了。** Cocos 的 Inspector 改动要点右上角绿色 ✓ 才写进 `.meta`；验证方式是读 `.meta` 的 `userData`，不是看界面。
6. **错误码是对外契约，不能凭"都算没登录"合并。** `2001 NOT_LOGGED_IN`（没带令牌）与 `2002 SESSION_EXPIRED`（令牌无效/过期）在契约里是两个不同的客户端动作（跳登录 vs 先静默刷新）。写鉴权分支时要对着错误码表逐条核。→ KB-FIX-20261023-03
7. **会自动生成文件树的工具（数据库/缓存/IDE 索引）一律把根目录设在 `.local/`。** `.gitignore`、根目录白名单、空目录扫描豁免是**三套独立清单**，`.local/` 是唯一三套都满足的位置。→ KB-FIX-20261023-04
8. **guard 的误报比漏报更危险。** 漏报只是漏了个洞，误报会让人习惯性忽略报告、最后关掉闸门。写正则要从最短和最长路径两头验证：`../account/repo.ts` 命中是对的，`../../gateway/handlers.ts` 也被同一段子串命中就是错的。→ KB-FIX-20261023-05
9. **设计"全局拦截"前先枚举所有接口，逐个问"拦它会不会让客户端失去自救能力"。** 版本闸拦住了给客户端送"你该升级"的 `config.manifest`，形成永久自锁。凡是为自救而存在的接口（配置清单、版本信息、健康检查、降级公告）都不能被它自己引入的闸门拦住。→ KB-FIX-20261023-06
10. **测试要能重复跑。** 探针最初假设"云端无存档、revision 从 1 开始"，第二次跑就对老玩家全红。改成先从 `save.pull` 读基线、断言 `base+1`，才成为可以天天跑的工具。另外 `snapshot` 是不透明负载，要验证"存的是哪一份"必须让两份内容本身可区分，否则会把测试自身的错判成服务端的错。
11. **"能跑通"和"语义对"是两件事。** 本轮 4 个问题里有 3 个（03/05/06）都是代码跑得好好的、`verify` 也绿，只是语义或工程口径不对。断言必须盯着**对外可观察的行为**写，不能只盯着"函数没抛异常"。
