   Recommendation: 加金币消耗（赶海票、加速卡、沉船信息、修理?? 维修被否）。也可以设"每日回收上限"或"按玩家等级设回收额度"。但用户选了不限额。所以要放"建议重新考虑"或者用其他消耗池：沉船信息（每天限购）、开锁工具（消耗品，用一次断）——这其实是个很好的金币池：普通300/精制2000/高级12000。只要玩家开箱需求大，金币就被吸走。可以让箱子产出足够多，使得开锁工具成为主要金币消耗。数值上：一个金锁箱出 4-8 件紫/金（价值 3000-20000+），要 4 个高级工具（48000 金币）→ 亏本？金锁箱期望 6 件，紫 60% 3000-19999 均价~8000，金 40% ≥20000 → 期望 6×(0.6×8000+0.4×25000)=6×14800=88800，花 48000 工具，仍赚。可接受。但普通玩家拿不到高级工具（每区服每天3个）。
   Actually a big issue: 金锁箱出 4-8 件紫/金，价值近 9 万，而普通锁箱只有几百。这个收益曲线极陡，配合"水面金锁箱 0.001%"没问题，但"沉船独家 8% 金锁"+"每日一海 0.2% 金锁"会大量产出金阶物品 → 金阶物品（≥20000）贬值、排行榜被金阶主导。这是经济与榜单的隐患。

6. **箱子价值与开锁成本倒挂**：铜箱原价 864（蓝），但铜箱配方=铜锭×4=720；铁箱 518=铁锭×4=432. 银锁 3440 vs 银锭2400+齿轮×2=466 → 银锁成本约 2866，售价 3440，OK. 金锁 29640 = 金锭24000+齿轮×3=699 → 24699. OK.
   但注意：箱子可以打造（木箱=木板4+铁钉=24+26=50 vs 售价 60），OK.
   真正的套利：可打造物原价=材料×1.2，回收=原价×50%=材料×0.6 → 打造再回收必亏 40%，安全。但"各地 ±30% 浮动"：在 -30% 的商人买材料，在 +30% 的商人卖成品？买入价 = 原价×0.7（卖价），回收 = 原价×0.5×1.3=0.65 → 仍亏。基本安全。不过物品"金币（钱币物品）"原价100，银币10，200 枚熔一锭 → 银锭 = 银币×200 = 2000 成本，但银锭原价 2400。金锭 = 金币×200 = 20000，原价 24000。这些钱币物品从箱子里出 → 相当于箱子直接给钱，且"金币物品"和货币金币同名 → UI 混淆风险（文中已注意到）。
   
   还有一个大问题：**"原价=商人卖价，回收=50%"** 使得任何掉落物的"价值"直接等于金币。而榜单按"总收益价值"计 → 榜单=金币产出。可刷（虽然在线校验）。
   
7. **断网可玩 vs 离线收益 vs 排行**：
   - 已定：主线本地存档；离线收获不计榜；野人离线袭击自动结算；员工离线只做当下任务；潮汐真实时间；食物按游戏日结算、关游戏不腐坏。
   - 冲突：离线野人袭击"自动结算"如果客户端算，玩家可以改本地存档/改时间 → 直接赢或无损。若服务器算，则纯离线（断网）时无法结算，需要上线补算；但"断网可玩"意味着玩家可能长时间不联网。需要明确：**离线结算以服务器时间为准，联网时补算；纯离线期间本地先给一个"暂定结果"，联网后以服务器为准**。否则必然被刷。
   - 更实际的建议：首版"离线袭击"改成**只在联网时结算**（登录时服务器结算），离线时玩家岛处于"免战"状态并明确提示"离线不受袭击"。这牺牲一点设计但换来零作弊面。这是重大建议。
   
8. **保护卡 vs 无预警袭击**：新手7天卡 + 无预警 + 野人 11.3 小时一波 → 新手有卡没事；但卡过期后玩家离线 12 小时以上必被打，且"进大门即失败、抢走大部分基础物资、守军永久死亡"。对休闲玩家（碎片时间、每天上线 1-2 次）来说，这是**卸载级挫败**。而且守军永久死亡 + 想招回来要再救 NPC → 惩罚链太长。
   Recommendation: 首版把"野人袭击"改成"可修复损失"：守军不永久死亡（重伤/降级），被抢只抢"露天+农田"的溢出的部分，且给"复仇/找回"玩法（打野人窝点拿回一部分）。这属于"已定设定"（永久死亡、大部分物资），所以要放"建议重新考虑"。
   Also 8-1 无保护期/不匹配 (PVP 第二版) — 第二版再说。

9. **塔防/回放/离线结算的技术量**：A* 寻路 + 9 兵种 + 4 岛模板 + 回放（存操作序列）+ 离线结算 + 三选一弩车升级 + 迷宫地形升高 → 这是整个项目里最重的一块，单它就 ≥3-4 周。而首版还要"深海五项玩法"。
   Recommendation: 首版塔防做成"极简版"：1 种岛模板、3 兵种（盾/弓/器械）、固定 2 个登陆口、回放只存"随机种子+编队"用同一套模拟重放（确定性模拟），不做逐帧录像。

10. **浮力/重量与房间堆叠**：核心规则"整船浮力≥整船总重量"，浮力=全部船体材料容量之和，材料本身也占容量 → 有个定义问题：如果材料的"容量"和"重量"是同一个数，则每块筏块净浮力=容量-自重，需要正的净值。数值上要保证 筏块容量 > 筏块自重，否则加筏块等于没加。这是必须明确的数值规则（建议：筏块容量=10，自重=4；房间框架自重=5；每层房间重量递增 → 逼玩家扩筏）。风险：没有数值表就做不出"能建/不能建"的反馈。
   另一个：房间统一大小、可往上加盖，但没有"层数上限"，也没有"建筑重量"表 → 玩家可以无限叠？被浮力限制。OK。

11. **技术架构问题**：
   - Cocos Creator 版本：建议 3.8.x LTS（微信/抖音小游戏原生支持、Spine、2D）。版本必须锁定，因为 3.8 之后 2D 管线差异。
   - 双平台一套代码：Cocos 构建时选 "微信小游戏"/"抖音小游戏" 目标，平台差异（登录、广告、分享、存储、排行榜、录屏、内容安全）通过 `IPlatform` 适配层 + 构建时宏 (`PLATFORM_WX`/`PLATFORM_DY`) 注入。代码里禁止直接 `wx.`，一律走 `Platform.xxx`。
   - 包体：微信主包 4MB（小游戏主包上限 4MB，分包总 20MB? 目前微信小游戏主包≤4MB，总包≤20MB，单分包≤? 实际是总 20MB）。抖音小游戏主包 4MB? 抖音小游戏目前主包限制 4MB，总 20MB 左右。要给的数量要谨慎——App 端主包大小不同。建议：主包只放"启动+浅海首场景+UI 框架+通用脚本"，其余按"海域/系统"分包：pkg_deepsea、pkg_island、pkg_td、pkg_activity。图集按系统切，首包图集只放浅海 20 个漂浮物 + UI 图标。
   - 存档：本地 localStorage（wx.setStorageSync / tt.setStorageSync）存 JSON，加版本号 + 迁移函数；**服务端另存一份**（登录时拉取、关键节点上传）。换手机找回：靠平台 openid 绑定的云存档。没有云存档 = 换手机丢档 = 差评。
   - 后端：推荐"微信云开发（云函数+云数据库）"起步 + 抽象出 HTTP API 层；或 一台轻量云服务器（Node/Fastify + Redis + MySQL）。给出规模-方案-成本对应表。
     关键：微信云开发只能被微信端调用（wx.cloud.callFunction），抖音端用不了；所以**双平台必须有一套平台无关的后端 HTTP 接口**，微信端可以用云开发做一层转发，或者直接自建。这是重要的架构结论：别把业务逻辑写进云函数专有 API。
   - 配置表：Excel → 脚本导出 JSON + TS 类型声明；线上热更配置走 CDN（小游戏可 downloadFile/缓存），版本号比对。
   - 防作弊：客户端只负责表现，**所有"进榜/进钱包/进他人可见"的数值都由服务器算**。本地存档可以被改，所以本地存档里的东西对服务器只作"参考"，服务器持有"权威快照"。这是最重要的原则。具体：
     - 改本地存档 → 服务器权威档覆盖；离线收益用服务器时间 + 上限公式。
     - 改内存/加速 → 关键操作（开箱、赶海、打捞稀有物）上报服务端复算；加速器检测（客户端帧时间异常）只做标记不做封禁。
     - 抓包改请求 → 所有请求带签名（HMAC + 时间戳 + nonce），服务端校验；数值服务端算。
     - 刷总价值榜 → 榜单只认服务器确认的事件；离线不计（已定）；上限校验（已定 10-1）。
   - 随机的可公示、可核对：**服务器发种子（seed）+ 客户端按确定性随机算法（如 xorshift/mulberry32）复现**；概率表在配置里，公示页直接读配置生成。这样"公示=实际"可验证。这是正确做法，且已定（10-8）方向一致。
   - 塔防离线结算：服务器用确定性模拟（固定 tick、定点数或整数运算），不依赖客户端浮点 → 客户端和服务器结果一致。回放 = 存种子 + 编队 + 时间轴事件，客户端重放。省空间。
   - 性能：2 核 4G 安卓、30 帧 → 同屏 20 漂浮物、图集 2048、对象池、避免每帧 new、DrawCall < 40、内存 < 200MB（微信小游戏建议 < 200MB，实际 iOS 上限更高，安卓低端 512MB 也有）。加载时间目标：首屏 < 8 秒（微信冷启动）。

# 一、八个最要命的硬伤（先解决这些，其他都是小事）

## 硬伤 1：5 周做不完，差 2.5–3 倍

**判断**：按 v5.5 第十一章清单逐项估工时（出钩 20h、打捞/对象池 30h、物品与配方 60h、制作/研究/自动合成 40h、船体浮力 50h、员工食物职业 40h、箱子开锁 30h、深海五项 80h、占岛 25h、塔防+9 兵种+回放 120h、商人 30h、榜单称号 30h、赶海 40h、聊天 30h、新手引导 15h、画质 25h、平台适配 25h、后端 60h、美术 100h+、提审修 bug 40h…）合计 **950–1200 小时**。5 周按每天 12 小时算是 420 小时。

**推荐**：5 周只做"浅海＋赶海＋省份榜"的垂直切片（第四部分给具体砍法），深海/岛/塔防整体推到第二期。
**备选**：① 延期到 12–16 周做现首版；② 5 周做"每个系统都有壳"的演示版（不建议，上不了线）。
**不这么做的风险**：半成品上线 → 差评 → 平台降权 → 没有第二次机会；或者无限延期，热情耗尽，项目烂尾。

## 硬伤 2：开锁经济是死循环（最严重的数值错误）

**判断**：已定"必须连续命中、中途失误归零、蓄力就断一根工具"，配上命中区 20/15/10/5%，期望消耗是：

| 锁 | 连中 | 命中区 | 期望尝试次数 | 按现价的开锁成本 | 箱内期望产出 | 结论 |
|---|---|---|---|---|---|---|
| 铁锁 | 1 | 20% | 5 次 | 300×5=1500 | 约 1400 | 打平 |
| 铜锁 | 2 | 15% | 1/0.15²≈44 次 | 300×44≈1.3 万 | 约 0.9 万 | **亏** |
| 银锁 | 3 | 10% | 1000 次 | 2000×1000=200 万 | 约 4.4 万 | **巨亏** |
| 金锁 | 4 | 5% | 16 万次 | 12000×16 万≈19 亿 | 约 13 万 | **永远开不了** |

再叠加"高级开锁工具每区服每天 3 个"——金锁箱在首版等于不可开启。

**推荐**：三件事一起改：① 命中区 **50/40/30/20%**；② **失败不清零**（累计命中，进度保留，只断工具）；③ 工具降价 **30/150/600**，高级工具改"每人每天 1 个可买"。
**备选**：① 保持失误归零，但命中区放大到 80/70/60/50%（基本白给，失去手感）；② 工具改"有耐久"（1 根 5 次），命中区不动。
**风险**：不改 = 玩家学会"只砸木箱"，开锁（首版一大块工作量）白做；金锁箱变装饰品。

## 硬伤 3：离线野人袭击＝首版最大流失点

**判断**："无预警 + 离线自动结算 + 战损永久死亡 + 抢大部分基础物资"，四件事叠一起。上班族早上回来看：兵全死、粮被抢、岛被打穿。
**推荐**：离线结算加"三限"——单次最多损失 30% 可抢物资、守军只受伤不死（在线才可能死）、离线最多结算 2 波，超出折算成"潮痕"式补偿。
**备选**：① 离线期间野人不来（只在线打）；② 维持现状但把新手保护期拉到 14 天。
**风险**：塔防是首版最贵的模块（约 120 小时），做出来却把人赶走，D1/D7 直接崩。

## 硬伤 4：排行榜实际是"在线时长榜"

**判断**：已定"每收获一件都算、丢了也算"＋"出钩不限次数、无体力" → 谁在线久谁分高。省份攀比（你看重的点之一）会变成挂机比赛。
**推荐**：榜分两路——① 省份总收益榜按 **"入库/卖出的有效价值"** 算（丢弃、损坏、离线不计）；② 另设"本周新高榜"（首次获得某品阶、首次通关赶海）。

## 硬伤 5：赶海（每日一海）公平性 + 票价公式

## A. 项目经理视角

**A1 目标与定位**
- 成功标准建议四道闸门（写进立项书 1 页）：① 手感验证——5 人试玩，70% 能在 30 秒内学会出钩；② 上线——提审通过、崩溃率 <1%；③ 数据——D1≥30%、D7≥10%、人均时长≥8 分钟、人均激励视频≥1.5 次、DAU 3000；④ 收入——DAU 1 万 × 1.5 次 × eCPM 30 元/千次 ≈ **450 元/天**（粗估，广告只能回本）。
- 用户画像：25–40 岁男性偏多，玩过 Raft / 饥荒 / 羊了个羊 / 无尽冬日；碎片 3–10 分钟。

**A2 范围**：见第四部分。变更管理：任何新想法必须填"三行单"——影响哪个系统 / 加几小时 / 砍什么换。另外，"砍深度不砍种类"这条已经失效（种类已经太多），**建议改成"砍种类保深度"**。

**A3 进度**（相对周，非绝对日期）
W0 立项书＋手续启动＋数值表 → W1 出钩原型＋真机试玩 → W2 打捞/制作/扩筏 → W3 钓鱼/商人/存档/省份榜 → W4 赶海＋新手引导＋提审包 → W5 内测修 bug＋提审 → W6–8 驳回缓冲＋灰度。
关键路径三条：**出钩手感**（所有系统都复用它，一卡全停）、**手续**（一卡不能上线）、**账号与存档**（一卡榜单/赶海做不了）。
提审预留：首次 3–7 工作日/次，常见驳回 3–5 次 → **留 2–3 周**。

**A4 资源与成本**（首版预算建议 5000–15000 元，不含人力）
美术：AI 生成＋素材店（商用授权）＋自己统一描边调色；图标外包 100 个×30–50 元 ≈ 3000–5000；素材包 1000–3000。
音效：CC0 免费库＋1–2 个付费包 200–500。
测试：每周 5 人 ×5 周，红包 0–500。
服务器：云开发 0–300 元/月（1k DAU）、500–2000（1 万）；自建轻量 60–150/月。
软著加急 300–1500；主体 0–2000；二手安卓测试机 500–1500；版号代办不建议首版做。

## C. 游戏 UI 设计师视角

**C1 直接给答案**
- 画风：**扁平卡通＋厚涂光影**（2D 俯视 45°），不要像素（100 个图标统一像素风更难）。参考 Raft 的物件质感＋《疯狂水世界》的色调＋《羊了个羊》的 UI 简洁度。
- 主色：海蓝 `#2E86C1`、木色 `#C98B4B`、高亮橙 `#F5A623`；背景压暗保证 UI 可读。
- 品质色：白 `#FFFFFF` / 绿 `#3FBF5F` / 蓝 `#3B82F6` / 紫 `#A855F7` / 金 `#F59E0B`，**每个品阶再加角标形状**（圆/方/菱/星/冠）照顾色弱。
- 适配：设计分辨率 750×1334，安全区适配（顶部刘海、底部手势条），平板两侧留边不拉伸，20:9 超长屏用"上下留海"。
- 单手：出钩在右下拇指弧区；底部一排 5 个主按钮（背包/建造/地图/活动/更多），**顶部只放不可点信息**。
- 主界面信息优先级：**浮力/重量（常驻，最重要）＞ 金币 ＞ 等级/经验 ＞ 潮汐倒计时 ＞ 活动红点**。
- 字体：思源黑体 / 阿里巴巴普惠体（免费商用），750 宽下最小 24px；数字用等宽变体。
- 图标：统一模板（描边 2px＋单色底＋1 点高光＋右下数量角标），100 个图标一次做完再进图集。
- 动效：出钩 0.15s、命中 0.3s、开箱 0.5s、升级 1s、建造 1.5s；低配只降背景/波纹/粒子，**UI 不降级**。
- 力度条色弱冗余：颜色＋刻度＋命中瞬间震动＋数字，三重提示。
- 美术来源：AI 生成（固定 prompt 模板）＋素材店（商用授权）＋自己改；**每张素材记来源和授权，存一张表**。

**C2 文件清单与优先级**
先做（3 天内，不然程序没法开工）：**风格板 3 张 → UI 规范（色值/字号/按钮尺寸/弹窗模板）→ 界面清单**。

## D. 游戏开发者视角

**D1 直接给方案**
- **Cocos Creator 版本：3.8.x LTS**（2D 稳定、微信/抖音构建链成熟）；别用 2.x，也别用 beta。
- 一套代码双平台：**平台适配层接口化**——`ILogin / IAd / IShare / IStorage / IRank / IPay / IAnalytics / IRecorder(抖音录屏)`，业务层只调接口，构建时按平台注入实现。**平台 API 绝不散落在业务代码里**，这是以后上 APP 唯一省事的路。
- 包体：微信主包 4MB（文档已定）、分包；抖音限制不同，**按平台最新文档核对**。首包放：首屏 UI＋浅海图集＋前 20 个图标＋字体子集；分包：深海/岛/塔防/活动。
- 存档：本地 JSON（压缩＋版本号＋校验和），关键节点上传云端；换手机走"账号绑定＋云端恢复"；升级用 `migrate(save, fromVersion)`。
- 后端：首版 **微信云开发 / 抖音云**（免运维），业务代码写成一薄层 Node，**不写死 wx.cloud**；接口：login / save / rank / chat / event / merchant / card。
- 断网同步：规则类（潮汐/员工产出/野人）本地算＋服务器按时间戳校验；榜单/赶海/沉船信息/商人 服务器算；冲突**服务器为准**，允许一次"回滚重放"。
- 防作弊分层：改存档→加密＋校验＋关键数值二次校验；改内存→只影响本地，榜不认；加速→服务器时间戳；抓包→HTTPS＋签名＋服务端复算；刷榜→种子复算＋理论上限。
- 随机：**全部服务器下发种子**（赶海必做，开箱/沉船至少服务端校验），公示表由配置表自动生成。
- 塔防：网格 ≤64×64 的 A*；离线结算＝固定步长确定性模拟；回放＝**事件流**（单位 id/类型/路径节点/时间/结果），<2KB/场，只存最近 5 场。
- 船体：数据结构＝层→房间→设施；浮力＝Σ材料容量，重量＝Σ(建筑＋货物＋员工)，用脏标记增量算。
- 性能：内存 <150MB、首包 <5s、对象池（漂浮物/飘字/特效）、图集 ≤2048、同屏 ≤20、三档降级。
- 配置：Excel → JSON（构建脚本＋字段校验＋版本号）；热更新走远程资源＋合法域名。

# 四、五个重点问题的正面回答

**① 一个人 5 周怎么砍才既按时又好玩？**
只保一条"能玩通且上头"的线：**出钩手感 → 打捞 → 制作 → 扩筏 → 钓鱼 → 商人 → 省份榜 → 赶海**。深海/岛/塔防/员工职业/电力/聊天/称号全部推后。理由：这 8 件事共同构成"3 分钟一局、每天回来一次"的完整闭环，且全部复用同一套出钩手感——**5 周里最值钱的是把手感调到爽，而不是把系统堆齐**。

**② 断网可玩 vs 排行榜公平怎么兼顾？**
双轨制，别追求绝对公平：**玩在本地，名次在服务器**。具体四条：本地存档负责游玩；榜单只认服务器能复算或能校验上限的数据；离线收益有上限（8 小时）且不计榜；赶海用"服务端发种子＋客户端传操作流＋服务端复算"。再加一条兜底：每周抽查异常存档（收益/时长比超阈值）。

**③ 双平台＋以后上 APP 怎么最省事？**
三层：**Core（纯 TS，零平台 API）/ Platform（接口化适配层）/ UI（Cocos 场景）**。服务器一套 HTTP+JSON API，账号做"平台 openid → 自建 uid"映射表；以后上 APP 只加 `LoginImpl(手机号/Apple)` 和 `PayImpl`，业务和服务器不动。这是唯一能避免"上 APP 重写一遍"的结构。

**④ 后端什么最便宜、最省运维、还能扛爆量？**
首版用**微信云开发/抖音云**（0 运维，1k DAU 近似免费，1 万 DAU 几百到两千/月）。把业务写成"薄云函数＋文档库/KV"，热点（榜单/聊天）加缓存和分片；日活到 10 万级时把这层 Node 代码整体搬到自建（Redis＋MySQL），**因为代码没写死平台 API，迁移是运维活不是重写活**。备选：首版直接一台轻量云服务器＋Redis（60–150/月，更可控，但要自己防挂）。

**⑤ 手续时间线和开发怎么并行？**
W0 就启动：主体认证（1–3 天）→ 软著（加急 3–10 工作日）→ 平台类目/备案（1–4 周）→ 版号（6–12 个月，纯广告路线下**先确认是否必须**）。开发侧 W4 出提审包，W5 首次提审，W6–8 留驳回缓冲。**结论：把"手续"当第 0 周任务，而不是上线前任务。**
