# 总纲：为什么这套结构专门为微信小游戏重新设计

通用 Web 工程规范（如你附件中的体系）解决的是"可持续演进的 Web 工程"问题。微信小游戏有四个本质差异，必须在结构上单独应对：

```text
差异维度          Web 工程              微信小游戏
───────────────────────────────────────────────────────
包体限制          几乎无限制            主包 4MB，总包 ~30MB（硬墙）
运行时环境        Node.js / 浏览器      微信小游戏运行时（V8，非浏览器）
渲染引擎          React / Vue DOM       Cocos Creator（Canvas/WebGL）
后端形态          常驻进程服务器        云函数（Serverless，按量付费）
开放域            无                    独立 JS 沙箱（好友排行榜专用）
存档              服务端 Session/DB     本地 wx.setStorage + 云端同步
平台 SDK          标准浏览器 API        wx.* 专属 API，抖音另一套
```

因此本规范在附件体系的**核心原则**（生命周期分类、依赖方向、业务边界）基础上，针对游戏引擎结构、包体治理、开放域、离线同步、配置表热更新等维度做了全面重新设计。

# 第二部分：客户端完整结构（Cocos Creator 3.x）

## 2.1 包体治理是客户端结构的第一约束

```text
微信小游戏包体规则（硬限制）：
┌─────────────────────────────────────────────────────┐
│  主包（main bundle）        ≤ 4 MB                  │
│  单个分包                   ≤ 20 MB                  │
│  所有包总计                 ≤ 30 MB（近期扩展后）     │
│  开放数据域包               独立计算，≤ 4 MB          │
└─────────────────────────────────────────────────────┘

主包只放：
  - 游戏引擎核心
  - 启动场景 + loading 界面
  - 浅海前 3 关的最小内容
  - 平台适配层（PlatformAdapter）
  - 核心框架代码（事件总线、存档管理）

其余全部放分包，按需加载。
```

# 第五部分：高效处理增删改查变更

## 5.1 变更类型判断流程

```text
收到一个新需求/变更，首先判断变更类型：

变更类型          影响范围                    操作流程
─────────────────────────────────────────────────────────────
A. 数值调整       只改配置表                  修改Excel → 运行导出工具 → 更新JSON → 热更新
B. UI变更         只改UI层                    修改prefab/panel脚本 → 不影响业务逻辑
C. 新玩法功能     新增模块                    按模块新增流程（见5.2节）
D. 新接口         shared/contracts + 云函数   按接口新增流程（见5.3节）
E. 存档结构变更   SaveSchema + SaveMigrator   按存档变更流程（见5.4节）
F. 新平台接入     PlatformAdapter新增实现     只改platform/层（见5.5节）

判断错误会导致：
  - 把数值写死在代码里（应在配置表）→ 改一个数要重新发包
  - 把接口格式散落在业务代码里（应在contracts）→ 前后端对不上
  - 不写SaveMigrator（应迁移旧存档）→ 老玩家存档读不出来
```

## 5.2 新增玩法功能的标准流程

以"新增钓鱼系统"为例：

```text

第2步：判断模块归属
  └── 属于深海玩法 → 新建 client/assets/_shared/scripts/modules/fishing/

第3步：新增模块目录结构
  modules/fishing/

  │   ├── FishingRod.ts       # 钓竿组件

  ├── systems/

第4步：更新配置表（Excel）
  tools/excel-to-json/configs/
  └── fish.xlsx               # 新增：鱼类型、稀有度、价值
  运行：make export-configs → 生成 fish.json → 放入 resources-config分包

第5步：如需新接口，按5.3节流程新增

第6步：如需新场景资源，放入对应分包（game-deep/）

  GameBootstrap.ts → 添加 FishingModule 注册
```

## 5.4 存档结构变更流程（最高风险操作）

```text
⚠️ 存档结构变更 = 所有在玩玩家的数据都受影响，必须有迁移脚本。

第1步：在 SaveSchema.ts 中新增版本
  export const SAVE_VERSION = 4  // 从3升到4
  export interface SaveDataV4 extends SaveDataV3 {
    fishingUnlocked: boolean      // 新增字段
  }

第2步：在 SaveMigrator.ts 新增迁移函数
  function migrateV3toV4(v3: SaveDataV3): SaveDataV4 {
    return {
      ...v3,
      fishingUnlocked: false      // 老玩家默认未解锁
    }
  }

第3步：在 SaveManager.ts 注册迁移路径
  migrateChain = [
    { from: 1, to: 2, fn: migrateV1toV2 },
    { from: 2, to: 3, fn: migrateV2toV3 },
    { from: 3, to: 4, fn: migrateV3toV4 },   // ← 新增
  ]

第4步：测试迁移
  .local/scratch/test-migration-v3-to-v4.ts
  # 用真实存档数据测试迁移结果

第5步：更新文档
  docs/04_technical/save-schema.md
  # 记录每个版本的变更内容和迁移逻辑
```

## 5.5 新增平台的标准流程

```text
以后要上iOS原生APP时：

第1步：新增 Adapter 实现
  client/.../platform/adapters/
  └── NativeAdapter.ts            # 实现 PlatformAdapter 接口

第2步：在 PlatformFactory.ts 新增判断
  if (isNativeApp()) return new NativeAdapter()

第3步：接入原生SDK
  # 替换：登录SDK、广告SDK（穿山甲/优量汇原生版）、分享SDK
  # 保持：所有业务逻辑代码零改动

第4步：接入文档
  docs/04_technical/platform-adapters.md
  # 记录原生平台的特殊处理事项
```

## 5.6 配置表（数值）变更流程（最高频操作）

```text
数值调整是最高频的操作，必须做到：改Excel→自动生成JSON→无需改代码→热更新推送

标准流程：
  1. 打开 tools/excel-to-json/configs/balance.xlsx
  2. 修改对应数值（例如：蓝色判定奖励倍数从1.5改为1.8）
  3. 运行：make export-configs
     → 自动生成 resources-config/configs/balance.json
  4. 提交并推送
     → CI 自动触发 config-version 云函数更新版本号
  5. 客户端下次启动：
     HotUpdateManager 检测到版本号变化
     → 仅下载 balance.json（几KB）
     → 不需要重新提审整个包
     → ConfigManager 刷新内存缓存
     → 所有系统自动使用新数值

make export-configs 做什么：
  - 读取所有 .xlsx 文件
  - 验证数据完整性（防止空格、类型错误）
  - 输出 JSON 到对应目录
  - 生成 manifest.json（含版本hash，用于热更新对比）
```

# 第七部分：文档与代码同步机制

文档最大的问题是"写了就过时"。以下机制让文档和代码保持同步：

## 7.1 文档-代码双向绑定规则

```text
规则：凡是在代码中有对应实现的设计文档，
      必须在代码文件顶部注释中注明对应文档路径。

/**
 * 浮力/重量计算系统
 * @design docs/01_product/design/raft-building.md#浮力系统

## POST /player/sync-save
- 实现位置：server/functions/player/handlers/syncSave.ts
- 请求契约：shared/contracts/player/SyncSaveRequest.ts
- 最后更新：2026-01-20（v1.2 新增离线收益字段）
```

## 7.2 变更联动检查表

```text
修改以下内容时，必须同步更新对应文档：
```

```markdown
### 包体硬限制（违反即提审失败）
- 主包（main bundle）：≤ 4 MB，超出立即报告，不要自行决定删减内容
- 任何场景、预制体、图集，修改后必须运行 `make check-bundle-size`

- **绝对禁止** 在 modules/ ui/ data/ 层直接调用 `wx.*` 或 `tt.*`

- **绝对禁止** 将数值硬编码在 .ts 文件中
- 所有游戏数值（物品价格/技能伤害/生产速率等）必须在 Excel 配置表中定义
- 修改数值：修改Excel → `make export-configs` → 提交JSON

### 存档约束
- 修改 `SaveSchema.ts` 的任何字段，必须同步创建对应的 `SaveMigrator` 迁移函数
- 不写迁移函数 = 老玩家存档损坏，这是最严重的线上事故
```

```makefile
	@VIOLATIONS=$$(grep -rn "wx\.\|tt\." \
	    client/assets/_shared/scripts/modules/ \
	    client/assets/_shared/scripts/ui/ \
	    client/assets/_shared/scripts/data/ \
	    2>/dev/null | grep -v "//.*wx\." || true); \
	if [ -n "$$VIOLATIONS" ]; then \
	    echo "❌ 发现直接调用wx.*，必须通过PlatformAdapter："; \
	    echo "$$VIOLATIONS"; exit 1; \
	fi
	@echo "✅ 平台API调用检查通过"

check-hardcoded-values:
	@echo "[ Guard ] 检查是否有硬编码数值（魔法数字）..."
	@echo "⚠️  此检查需要人工审查，请确认没有把游戏数值写死在代码里"
	@echo "✅ 请确认后继续"

ci: guard
	@echo "[ CI ] 运行测试..."
	cd server && npm test
	make export-configs
	make check-bundle
	@echo "✅ CI全部通过"

clean:
	rm -rf .local/runtime/ client/temp/ server/.serverless/
	find . -name "*.log" -not -path "./.git/*" -delete 2>/dev/null || true
	@echo "✅ 清理完成"
```

# 第十部分：核心规则浓缩（微信小游戏版）

```text
1. 包体是硬墙，不是软建议。
   主包≤4MB，超出即失败。每次改动都要 make check-bundle。

2. 平台适配层是唯一出口。
   wx.*/tt.* 只在 platform/adapters/ 里出现，其他地方零容忍。
   换平台时，只改适配器，业务逻辑零修改。

3. 配置表是数值的唯一真相来源。
   任何数字（价格/伤害/概率）写死在代码里 = 技术债，
   改一次就要重新提审。

4. 存档迁移是对老玩家的承诺。
   改存档结构不写迁移函数 = 老玩家数据损坏 = 差评 + 卸载。

5. 排行榜数据只信服务端。
   客户端上报的分数不可信，服务端必须独立校验，
   否则刷榜者一天内摧毁整个榜单的公信力。

6. 文档与代码同步，不是事后补。
   设计文档写清楚再动手，实现完成后标记"已实现"，
   不同步的文档比没有文档更危险（误导自己和AI）。

7. .local/ 是临时状态的黑洞。
   截图/日志/草稿/AI产物全进 .local/，
   它完全被 gitignore，不污染仓库。

8. contracts/ 是前后端的唯一协议。
   接口格式只在 shared/contracts/ 里定义，
   改接口时两端同时改，TypeScript 编译时报错比运行时报错好无数倍。

9. 模块只对外暴露入口文件。
   modules/hook/HookModule.ts 是外界唯一的访问入口，
   内部实现随时可以重构，不影响其他模块。

10. 一个文件有且只有一个显而易见的正确位置。
    如果不确定放哪，先看文件归属速查表，
    还不确定就问（不要创建，先明确归属）。
```
