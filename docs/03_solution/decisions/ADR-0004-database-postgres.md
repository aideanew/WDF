# 数据库：PostgreSQL（Redis 推迟）

## 决定（已定·Hark代定 2026-10-23 10:45）
**PostgreSQL，单库**：事务 + 唯一约束保障流水与幂等；jsonb 存存档；收益事件按日分区；排行读快照表。

**Redis 暂不上**：~~日活与排行榜压测达不到要求时再加，不作为首发依赖。~~ 是否引入由下列压测门槛决定（【可调】，已定·Hark代定 2026-10-23 11:18）。

## 压测门槛（【可调】已定·Hark代定 2026-10-23 11:18）

环境：**2 核 4G**（与 ADR-0003 同规格）、**单区**压测。

**同时**达到以下三条，才算达标、**不加 Redis**：

| # | 指标 | 门槛 |
|---|---|---|
| 1 | 同时在线 | **500 人** |
| 2 | 排行榜吞吐 | **读 200 QPS、写 100 QPS** |
| 3 | 延迟与错误 | 上述两类请求 **P99 ≤ 200 毫秒**、错误率 **< 0.1%** |

**不达标时的处理顺序（不得跳步）**
1. 先加索引、改查询，**再测一次**；
2. 仍不达标，才加 Redis；
3. 加 Redis 后再测，指标与门槛不变。

任务卡：`docs/05_execution/tasks/TASK-0903.md`（挂排行榜切片 S9）。

## 后果
迁移用顺序 SQL 文件；已执行迁移不可修改。上线前必须按上表做一次排行榜压测，用数据决定是否引入 Redis。
