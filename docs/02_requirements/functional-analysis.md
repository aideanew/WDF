# 功能与需求分析

> 目的：把已定设计翻译成“系统要支持什么”，作为目录、模块、接口、数据设计的输入。**这里只做归纳，不改设计**；设计细节以 v5.5 为准。

## 1. 产品骨架
- 入口：微信小游戏、抖音小游戏、未来 APP；共用一套前后端；未绑定前各平台账号与存档独立，绑定微信+抖音后为同一账号。
- 核心循环：出钩捞物 → 制作 → 扩筏/加层 → 员工经营 → 驶出浅海（20 级深海）→ 占岛/塔防 → 赶海与省份榜 → 回到出钩。
- 时间节奏：秒级（出钩 1.2 秒力度条）· 分钟级（潮汐 10 分钟、赶海 3 分钟）· 小时级（潮汐每 6 小时、员工产出、野人航行）· 日级（赶海 20:00–21:00、每日限量）· 赛季级（排行与称号）。

## 3. 由功能推出的系统级需求

| 编号 | 需求 | 来自 | 落到哪里 |
|---|---|---|---|
| SR-01 | 同一规则客户端与服务端结果一致（写操作以服务器为准） | 必须联网 + 赶海/排行复核 + 塔防回放 | `packages/game-core`（确定性） |
| SR-02 | 平台差异只在适配层 | 三入口一套逻辑 | `client/.../platform/` + 构建期常量 |
| SR-03 | 账号身份映射与合并 | 绑定后同一账号 | `account` + `identity` 表 |
| SR-04 | 数值可调且不改代码、不重新提审 | 数值暂定、后续调平衡 | `game-data` + 数值热更包 |
| SR-05 | 存档可升级、可分叉选择、绝不相加 | 双端、换机 | `game-core/save` + `save` 模块 |
| SR-06 | 服务器时间为准 | 潮汐、赶海、限量、保护卡 | 响应 `t` + 客户端偏移 |
| SR-07 | 写操作幂等 | 广告、限量、赶海结算 | `rid` + `idempotency` 表 |
| SR-08 | 包体：主包 ≤4MB，双平台总 ≤20MB | 官方限制 | Asset Bundle 规划 |
| SR-09 | 低配 30 帧、同屏漂浮物 ≤20 | 已定 | 对象池、固定步长、画质三档 |
| SR-10 | 20:00 峰值可承载 | 赶海集中开场 | 网关限流、开场预热、场次锁定配置 |
| SR-11 | 可降级、可回滚 | 一人运维 | `ops` 开关、`config_release` |
| SR-12 | 断网不能继续游戏（提示后暂停），不能绕过防沉迷 | 合规 | `compliance` 启动联网校验 |

## 4. 非功能需求（详见 `non-functional/`）
- 性能：低端安卓 30 帧；避免 >100ms 卡顿；首次可操作 P90 ≤5 秒（弱网 ≤8 秒）；内存 180–250MB（目标值）。
- 体积：主包 ≤3.5MB（留余量）；存档 ≤300KB。
- 可用性：接口 P95 <300ms（目标值）；赶海开场 5 分钟窗口压测通过。
- 安全：竞争数据只信服务器；HTTPS + 会话令牌；限流。
- 可维护：`npm run verify` 全绿才能提交。

## 5. 已澄清点（Hark 代定 2026-10-23 10:45）
1. 沉船信息份数：**每个玩家各刷各的，互不抢**（不再是“本区服共享 100 份”）。
2. 高地拆掉后：**恢复成平地，可以再升一次**，重新付材料、已消耗的不返还。
3. 赶海计分（已定·Hark代定 2026-10-23 11:18）：~~按每件捆到的物品在《材料与工具总表》里的价格相加；同分先达到者在前。~~ 按每件捆到的物品**以及箱子本身**在《材料与工具总表》里的价格相加；同分先达到者在前。箱子若在总表里没有价格，列入未知登记册，不得自编数字。
4. 占岛：**不算主动进攻**，占无主岛不触发任何对抗；清野人岛是 PVE。
5. 浅海第一个员工：**新手引导里救起一个落水者**，当第一个工人。
6. 玩家航速：由帆 / 引擎等装备决定，数值进 game-data；初始值按“基础筏横穿深海一边（800 km）约 30 分钟实时”反推，标【可调】，靠试玩调。
> 另：10-23 10:45 起沉船份数不再是服务器共享库存 → `salvage` 的份数表按玩家维度建；其余各项只改数值表或 game-core 内部规则，不改目录。
