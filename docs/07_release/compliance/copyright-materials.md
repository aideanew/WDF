# 软著提交材料清单

> 依据：`【已定·Hark代定 2026-10-23 11:18】`——软著**这周内提交申请，一定在微信上线之前**；**软著提交 ≤ 10-30**（见 `docs/04_planning/lifecycle.md` M-资质-1）。不加急、自己办（中国版权保护中心）。
> 软件名称与小游戏名一致：**我的筏不可能这么大**。

## 1. 必须准备的四样

| # | 材料 | 要求 | 状态 |
|---|---|---|---|
| 1 | **源程序** | 前 30 页 + 后 30 页，共 60 页；每页 ≥50 行（不足 50 行的按实际）；页眉写软件名称 + 版本号，页脚连续页码 | 待准备 |
| 2 | **操作说明书** | 图文对照，覆盖启动 → 出钩 → 制作 → 扩筏 → 岛屿/塔防 → 赶海/榜单的主要流程；页眉同上 | 待准备 |
| 3 | **申请表** | 中国版权保护中心线上填报（个人主体）；著作权人 = 个人真实姓名；开发完成日期、首次发表日期如实填 | 待填 |
| 4 | **身份证明** | 个人：身份证正反面复印件/扫描件 | 待准备 |

## 2. 源程序的具体做法（关键，容易被打回）

- 只放**自己写的代码**：`client/assets/scripts/**`、`packages/**`、`server/src/**`、`tools/**`；**不要**放第三方库、Cocos 引擎源码、`node_modules`、生成物（`client/assets/scripts/generated/**`）。
- 顺序：按目录自然顺序（client → packages → server → tools），前 30 页取开头、后 30 页取结尾，**中间不需要**。
- 每页加页眉「我的筏不可能这么大 V1.0」与页码；行号不必加。
- 若总代码不足 60 页：按实际页数提交（不足 3000 行的可以全部提交）。
- 导出为 **PDF**，不要交散图。

## 3. 操作说明书的具体做法

- 图文对照：每步一张截图 + 一句说明（"点哪里、发生什么"）。
- 必含章节：启动与登录、出钩打捞、制作与背包、扩筏（浮力/重量）、员工与食物、上岛与塔防、每日一海与排行榜。
- 与当前版本一致；**不写未上线功能**（远洋、PVP、交易等 v2.0 内容不要写进去）。
- 页眉与源程序一致。

## 4. 时间与流程

| 步骤 | 时间要求 | 产出 |
|---|---|---|
| 准备四样材料 | **≤ 2026-10-30** | 源程序 PDF、说明书 PDF、申请表、身份证明 |
| 线上提交 | 与上同一节点 | 提交回执（存 `EVD`/本地备份） |
| 受理 → 下证 | 自办常见 1–3 个月，**时间不可控**（见 `risks.md`） | 软著证书 |

流程：提交 → 受理 → 审查（可能补正）→ 下发证书。**收到补正通知要在期限内改**，否则重排。

## 5. 与其他事项的关系

- **微信上线不等下证**（微信纯广告一般不要软著），但**软著必须在微信上线前提交**。
- **抖音提审必须等下证**（M-资质-3）。
- 全流程与里程碑见 `docs/04_planning/lifecycle.md`；进度登记见 [filings.md](filings.md)。
