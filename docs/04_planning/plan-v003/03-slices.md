# 03 · 垂直切片

> 每一刀结束，玩家主路径必须**多一个可演示行为**；刀与刀之间只通过契约/文件解耦，不互相等。

## 3.1 切片清单与排序

| 切片 | 内容（端到端可演示） | 前置 | 为什么排这里 |
|---|---|---|---|
| **S11 数值清欠** | 用户裁决 D-01~D-10 → 转录 → `gen:config` 行数上涨 + configVersion 变化 → 41→35 空表 | 无（裁决清单即 02 §2.4） | **解锁力最大**：8 个 todo handler 与 10 字段全堵在这；且不裁决任何其他刀都白排 |
| **S12 权威背包+商人回收** | 背包页点"回收"→ 确认弹窗 → `economy.sell` → 灵草入账 + `ledger_entry` 流水 → 商人页可卖出 | S11(D-01/D-07) + D-11 裁决 | v1.0 主玩法增量（期次已定）；**必须先 ADR-0012 否则是假权威**（F-15） |
| **S13 开锁+ salvage.claimInfo** | 打捞到上锁箱 → 开锁小交互（hits_required 连点）→ 箱开 → 物品入包 | S11(D-08/D-09) | locks 5 行/chests 3 行**数值壳已在**，只差 2 字段；是"最小成本新增玩法" |
| **S14 真机验证** | 四面板录屏 + 首钩命中率采样 + 6 态真机走查 + **主包体积实测** | 无（不依赖任何裁决） | **低成本高信息量**：命中率/包体数据会反过来修正 S11/S15 的优先级；且 M1 出口欠着这项（D-04） |
| **S15 合规与包体** | 软著/备案材料清单落 docs/07_release；包体超标的瘦身任务（动态加载 b-* bundle） | S14（需实测数据） | v1.0 出口第 4 件；没有 S14 数据就无法判断是否要瘦身 |
| **S16 契约解冻执行** | 用户裁决 D-11~D-14 后：2004 码 + error-catalog + UX 映射一行 + 测试 | D-11~D-14 裁决 + S12 | 解冻是**高成本动作**（change-playbook 联动 4 处），集中一次做，避免反复冻融 |

## 3.2 关键排序原则（辩证结论）

1. **先解阻塞、再写功能**：S11 在最前。反证：若先做 S12，merchants 无数值 → 执行者要么自编（违反 E-06）要么空转。
2. **先裁决、再解冻**：S16 在最后且批量。反证：每裁决一项就解冻一次，change-playbook 联动成本 ×N。
3. **验证刀不等人**：S14 与 S11 并行（无共享可变状态：一个动 game-data/裁决文档，一个动真机+测量脚本）。
4. **第一刀是步行骨架性质**：S11 本身不改玩法代码，但它的"裁决→转录→gen:config→守卫绿"是后续所有刀的**数据步行骨架**（与 plan-v001 §5.3 第一刀定义同构）。

## 3.3 可并行判定（机械规则）

| 组 | 满足条件 | 结论 |
|---|---|---|
| S11 ∥ S14 | ①无共享可变状态（game-data+docs vs 真机+脚本）②无契约依赖 ③文件所有权不相交 ④不共用迁移 | **可并行** |
| S12 → S13 | 共享 `economy/ledger` 写路径与 inventory 写回 | **串行**（S12 先） |
| S15 依 S14 | 需要包体实测数据 | **串行** |
| S16 依裁决+S12 | 解冻含 economy.sell 相关错误码语义 | **串行收尾** |
