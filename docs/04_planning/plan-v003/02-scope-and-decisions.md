# 02 · 范围复核与裁决清单

## 2.1 一段话复述

把 M1 已打通的"打捞→背包→合成→榜单→云存档"闭环，升级为**可提交审核的 v1.0**：
补上商人/回收（期次已拍板进 v1.0）、开锁、真机验证与包体合规四件事；
而这一切的前置是**把 41 张空表与 10 个空字段的数值欠账，转化为用户可逐项拍板的裁决清单**——
E-06 铁律（`game-data/UNKNOWN-TABLES.md` 头部）禁止任何人在文档缺值时自编数值。

## 2.3 冲突检查（逐条，含反证）

1. **MUST-② 与 MUST-① 存在顺序耦合**：数值清零后若权威背包未定，回收/商人实现会被推翻。→ 反证：可以先做与背包无关的纯展示功能。**结论：权威背包 ADR 必须排在商人/回收实现之前**（DAG 见 04）。
2. **MUST NOT"不自编数值" 与 v1.0 工期的冲突**：41 张表若全等设计文档，v1.0 无限期拖延。→ 统一方案见 §2.4：把缺值**结构化为"建议默认值+依据"**，由用户拍板后即合法。
3. **MUST NOT"S8 移 v1.1" 与 contracts 已冻结 `event.*` 三动作**的张力：契约先于期次存在。→ 不解冻、不实现、不删（todo 保持），W4 一并处理载体缺口（F-10）。

## 2.6 隐含要求与前置条件（需求没写但执行必需）

1. 商人"限购"需要**每日重置机制**——现有 `economy.buyQuota` 契约已有配额语义，但**日界归属由服务端时区还是 UTC 未定义** → 并入 D-11 的 ADR-0012 一并定。
2. 开锁需要**锁与箱的关联关系**（chests.lock 已填 none/iron/copper/silver/gold，D-08 拍板后即可用）。
3. 回收触发点在背包页（A-3 的行按钮），需要 `navigate` 之外新增**确认弹窗**组件 → 并入 W2 任务卡。
4. 包体 ≤4MB 的测量方法未定（Cocos 构建产物目录）→ W3 卡里定义（build/web-mobile 体积脚本）。
