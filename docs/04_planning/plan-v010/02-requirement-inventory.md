# 02 · 未被实现需求总账

> 本文件是本版**唯一的需求完成度权威**。任何"v1.0 完成了多少"的口径必须引用本表。
> 判定口径：某一层**有真实行为**才算 ✅；只有目录/常量/注释算 🅾（空壳）；有代码但被占位数据一票否决算 ⚠。

## 1. 复述与拆解

**项目要解决的核心问题**：做一款「出钩打捞 → 制作 → 扩筏 → 员工经营 → 驶出浅海 → 占岛塔防」的微信小游戏，
三平台（微信/抖音/未来 APP）共用一套前后端，**必须联网**（ADR-0008），服务器为竞争数据的唯一权威。

**用户**：微信小游戏玩家（低端安卓为主要性能基线）。
**管理端**：**不做界面**，只有脚本 + SQL（`mvp-scope.md:56`）→ 因此本规划**不含任何后台管理 UI 任务**。
**系统边界**：客户端（Cocos 3.8.8）+ 网关（Fastify 5 + PGlite）+ 纯规则包（game-core）+ 数值包（game-data）。

## 3. 第三类：「写了代码，但输入是占位值，等于没写」

这一类最危险——它有函数、有类型、有注释，看起来像实现，**且永远不会被测试抓到**，
因为测试用的也是同一份占位数据。

| 模块 | 代码 | 一票否决的证据 |
|---|---|---|
| **raft 浮力** | `remainingBuoyancy()` / `checkChange()` 完整实现 | `items.capacity` **全表唯一值 `0`** → 浮力恒 `0×n - (货重 + 1×n)` **恒为负** → `checkChange` 对任何非空船体都返回"浮力不足" → **扩筏永远失败** |
| **sea 潮汐** | 19 行（时间窗计算） | `tides` 0 行 → 无周期参数 |
| **defense 塔防** | 30 行（确定性模拟骨架） | `units/waves/defenses` 全 0 行 → 无兵种、无波次、无防御设施 |
| **chest 开锁** | `game-core/chest` 有 `attempt()` | `drops` 0 行 + 设计源 `对话讨论.txt:4247` 把"开箱出什么"列为**待回答问题** → 现在只有 D-27 保底 `item_0020` |

> **`items.weight` 全 1 / `capacity` 全 0 的来历**：`game-data/UNKNOWN-TABLES.md §三` 写明
> 这是 **D-07 裁决值**（原设计文档没给）。它的语义是"占位以保证 schema 非空"，
> **不是"每个物品重 1、每个材料浮力 0"**。
> ⇒ 一旦有人把 `raft` 当"已实现"来排期，就会得到一个必然失败的模块。**这是本版最重要的单条发现。**

## 8. 本文件的自我限制

1. 行数是粗筛。`leaderboard` 的 game-core 只有 4 行（`MODULE_ID` + 常量），
   但服务端 283 行是真实实现 → 判"部分完成"而非"未实现"，因为榜单的计算在服务端。
2. **本表不判断工作量**，只判断"在不在"。工作量见 `05-slices-and-cards.md` 的规模列。
3. `guide` / `settings` 判"完成"是因为**客户端行为真实存在**，但它们没有自动化测试
   （Cocos 运行时不可注入）→ 这是 v009 已登记的既有限制，不是本版新增缺口。
