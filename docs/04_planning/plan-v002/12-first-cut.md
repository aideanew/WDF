# 12 第一刀与启动顺序

## 12.1 为什么第一刀是"契约补缺"而不是"出钩"
- plan-v001 的第一刀 S1（步行骨架）**主体已完成**：Boot/存档/push/错误封套都通了（01 §1、`BootController.ts`）。
- 现在真正的瓶颈是：**契约未完全冻结**（chest/ops 无类型、错误路径表缺）→ 若直接上手写 14 个 handler，各人各写字段，融合必乱。
- 因此第一刀 = `AT-2001`（0.5d，串行闸门）：把 chest 类型 + 14 错误码路径表补齐，`npm run sync` 后，后续所有 AT 才有统一语言。

## 12.3 关键路径与工期
```
AT-2001(0.5) → AT-2101(1) → AT-2102(1) → AT-2103(0.5) ≈ 3 人日（Core+Client 串行）
```
Server 侧 2201~2204 约 3.5 人日、与 Core/Client **并行**开展，不增加关键路径。

## 12.4 下发前必须先拿到的裁决（否则不许开工）
- Q-1（是否接受"算法+契约+测试优先"）—— 决定本轮范围。
- Q-2/Q-5（数值是否可补）—— 决定 S3+ 是否解锁。
- Q-3（daily_quota 口径）—— 只影响 `economy.buyQuota`，本轮不做，可后置。
- Q-4（是否落 0002/0003）—— 本轮只落文本，不执行，除非用户批准。

## 12.5 一句话结论
**先补契约（AT-2001），再并行开"hook 核心 + 不依赖数值的 4 组 handler + 开锁状态机"，全程用测试收紧；数值型 UI 与塔防/深海/赶海一律等数值与裁决。**
