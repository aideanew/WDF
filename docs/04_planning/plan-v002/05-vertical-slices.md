## 5.2 ★ 本轮新增切片（把"能做且高价值"的提前）

### S2a · 出钩算法（game-core/hook）—— **最高优先，解 C1 核心**
- **演示**：给定 `powerBp(0-10000)` + `angle` + 目标距离 → 确定性返回"命中/未命中 + 回手耗时"。同输入同输出。
- **为什么能先做**：算法不依赖最终数值——力度曲线参数、命中半径**由调用方传入**（未来从 `hooks/lines` 表读），因此**不被数值表阻塞**。
- **不得**：用 `Math.random`/`Date.now`/`cc`（AGENTS §2，determinism 测试强制）。
- **验收**：`tests/determinism/hook.test.mjs` 同种子同序列、边界（powerBp=0/10000）、命中半径单调性。

### S2b · 出钩表现（HookView，程序化 UI）
- **演示**：屏幕上一条 1.2s 往返力度条（蓝→绿→红），长按蓄力、松手发射、命中反馈。
- **参照**：今日 BootController 已证明"无 prefab 纯代码建 UI + Graphics"可行（`BootController.ts`）。
- **验收**：手工演示 + 埋点 `hook.hit/miss`（首钩命中率可测）。

### S5' · `save.resolveFork` 落地
- **演示**：制造分叉 → 后到者拿 conflict → 选一边 → 存档收敛。
- **不依赖数值**；依赖 `save_fork` 表（已存在）。

### S9' · `leaderboard.report/query` 落地
- **演示**：上报一次有效收益 → 写入 `income_daily`/快照 → 查询返回榜单。
- **不依赖数值**；可先按"存入/售出有效价值"求和（口径见 functional-analysis §5.3）。

### S7' · 开锁状态机
- **演示**：一局连中 → 失误不重置已中数 → 工具用一次断一根。
- 原子规则 `chest/index.ts` 已有，补状态机 + 工具消耗。

### S-CONTRACT · 契约补缺（串行，先于并行）
- `chest` 业务类型 + 错误路径对照表 + `ops` 类型占位。

### S-TEST · 测试补强（贯穿，本轮硬要求）
- handler 单元测试（14 todo 中已实现的逐个补）、determinism/hook、e2e 骨架 1 条。
