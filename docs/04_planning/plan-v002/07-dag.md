# 07 依赖 DAG

> 并行判据（机械规则，不靠主观）：可并行 ⟺ ① 无共享可变状态 ∧ ② 依赖契约已冻结 ∧ ③ 文件所有权不相交 ∧ ④ 不共用同一迁移版本号。**任一条不满足即串行。**

## 7.1 节点与边

```
AT-2001（契约补缺·串行闸门）
   ├─> AT-2101（hook 算法）
   ├─> AT-2201（bind）
   ├─> AT-2202（resolveFork）
   ├─> AT-2203（leaderboard）
   └─> AT-2204（telemetry）

AT-2101 ─> AT-2102（HookView）─> AT-2103（接线）
AT-2301（开锁状态机）         —— 无前置，独立
AT-2401（测试补强）           —— 依赖 2201/2202/2203/2204 落地后补全
AT-2402（e2e 骨架）           —— 可选依赖 2202
AT-2501（文档返工）           —— 无前置，独立
```

## 7.2 并行组（每条附满足依据）

| 组 | 成员 | ①无共享可变状态 | ②契约已冻结 | ③所有权不相交 | ④迁移不共用 | 允许并行 |
|---|---|---|---|---|---|---|
| G1 | AT-2101 ⟂ AT-2201 ⟂ AT-2202 ⟂ AT-2203 ⟂ AT-2204 | ✅ | ✅（2001 已冻结） | ⚠️ **2201/2202/2203/2204 都改 `gateway/handlers.ts`** | ✅ | **部分**：跨 Core/Server 可并行；**同属 Server 的 4 个必须串行**（见 08 重叠处理） |
| G2 | AT-2301 ⟂ 任意 | ✅（只改 chest） | ✅ | ✅ | ✅ | ✅ |
| G3 | AT-2501 ⟂ 任意 | ✅（只改文档） | ✅ | ✅ | ✅ | ✅ |

## 7.3 必须串行链

| 链 | 原因 |
|---|---|
| AT-2001 → 所有 handler/AT-2101 | 契约未补缺（chest/错误表）前，实现会各写各的 |
| AT-2101 → AT-2102 → AT-2103 | 表现依赖算法、接线依赖表现 |
| AT-2201 → AT-2202 → AT-2203 → AT-2204（**仅限 handler 注册那行**） | 同一文件 `gateway/handlers.ts`，合并时冲突 |
| `0002`/`0003` 迁移 | 版本号不得并行（本规划只落文本，执行待裁决） |

## 7.4 关键路径（决定本轮工期）

```
AT-2001(0.5d) → AT-2101(1d) → AT-2102(1d) → AT-2103(0.5d) = 3.0d
```
（Server 侧 2201~2204 可与 2101/2102 并行，不进入关键路径；AT-2301/2401/2402/2501 为填充）

**本轮关键路径 ≈ 3 个工作日**（单 Agent 串行 Core+Client 时）。

## 7.5 环检测

遍历全部边：`2001→21xx`、`21xx→21xx`（单调前进）、`22xx` 互不相连（仅共享文件，靠串行）、`2401→22xx`（单向）。**无环**（已确认）。

## 7.6 并行纪律（写给执行者）
- ✅ 允许：不同所有权 + 同一冻结契约 + 不改同一迁移。
- ❌ 禁止：同时改 `contracts`；同时改 `gateway/handlers.ts`（须串行）；一边改错误码一边让前端猜字段。
