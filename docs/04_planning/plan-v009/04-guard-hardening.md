# 04 · 闸门加固设计

## 1. 问题：闸门的三次"假绿"

同一类事故在本项目发生了三次，形态一次比一次隐蔽：

| # | 形态 | 具体事故 | 为什么当时没被发现 |
|---|---|---|---|
| 1 | **过滤式吞掉真错** | `tsc \| grep 项目路径` 漏掉 `services/**`，把 7 个真错误过滤成"零错误" | 过滤式本身是被当成"清理噪声"引入的 |
| 2 | **校验缺失让错误数据无害化** | 12 个测试文件写死过期 `configVersion 16921d30a67a934f`，一直绿着 | `gateway/version.ts` 的 cfg 校验**从未实现** → 错误数据不影响任何断言 |
| 3 | **闸门没接电** | `verify` 不含 tsc；client 1 错 + server 11 错在"全绿"里躺了两代规划 | `verify` 的名字叫"验收"，看着很权威 |

**共同结构**：每一次都是「**检查看起来存在，实际不产出信号**」。

- 第 1 次：检查存在，信号被管道吃掉。
- 第 2 次：检查存在（字段被发送），接收端不处理。
- 第 3 次：检查**不存在**，但名字让人以为存在。

## 2. 设计原则

> **闸门的第一属性不是"严格"，是"会响"。**
> 一个只会在被人工正确调用时才响的检查，不是闸门。

三条硬规则：

1. **`verify` 是唯一入口。** 任何检查只要不在 `verify` 里，就写进"已知债"清单，**且不得在任何汇报里当作"已完成"的证据**。
2. **不许用管道过滤后再判断。** 需要过滤 = 上游配置错。修上游（TASK-6002），不在下游过滤。
3. **闸门的"成功"必须是变红过。** 新增闸门时，第一件事是验证它能报出**已知存在的错**（TASK-6001 的验收就是 `exit=1`）。

**注**：`npm run verify` 目前**不含**双端一致性（需网络 fetch，不适合放门禁）。保持现状，但汇报时必须分开念。

## 4. 事实基线作为可交付物（治 F-45 的根）

### 4.1 问题

F-45 的根因不是"助手不严谨"，是**助手没有被交付事实基线**：

- 它不知道 `plan-v008` 存在 → 指针写回 v007。
- 它不知道 `1bc9bbf` 把 configVersion 更正为 `c6a54f0fb00341c5` → 带回了 `16921d30a67a934f`。
- 它不知道 `compliance` 是桩 → 写了"已接入防沉迷"。

**在缺事实基线的状态下写"事实类文档"，产出必然是编的。** 这不是态度问题，是信息问题。

### 4.2 方案：一张机器可读的事实卡

新建 `docs/04_planning/FACT-CARD.md`（或 `.json`），由 `npm run gen` 自动生成，**任何并行工作者开工前必须先读它**。

建议字段：

```yaml
generated_at: "2026-10-27T20:46:08+08:00"
git_commit: "1bc9bbf"
configVersion: "c6a54f0fb00341c5"        # 从 _manifest.json 读，不手写
clientVersion: "v0.1.0-s1"
gates: { test: "156/156", guard: "9/9", client_tsc: 1, server_tsc: 11 }
current_plan: "plan-v009"                 # 现行规划目录名
not_implemented:                          # ★ 最关键的一段
  - 实名/防沉迷（compliance/service.ts:4 为桩）
  - 隐私协议弹窗
  - 限流（ratelimit.ts 零引用）
  - 开锁（v1.0 不做，chests.lock 全 none）
  - cfg 回传（RpcResponse.cfg 从未赋值）
```

**关键点：`not_implemented` 段必须由代码扫描生成，不能手维护。**
判据可以是「文件存在但导出符号零引用」「接口存在但 `grep` 零调用」这类可机检的规则。

### 4.3 为什么这条值得做

本项目已经出现过**三个**不同来源的过度宣称：

| 来源 | 宣称 | 实际 |
|---|---|---|
| 我方（`plan-v008` §12） | 「合规材料已就绪」 | F-36/F-44 假话仍在 |
| 助手线（`current-plan.md`） | 「相关问题已修复，合规材料已就绪」 | 同上 |
| 助手线（`copyright-materials.md`） | 「已接入防沉迷」 | 桩 |

三次同源。**说明"要求人诚实"这条路已经证明无效**，得改成"让不诚实的成本变高"——即**让假话与可机检的事实卡对不上**。

**本版不做**（不属 P0）：事实卡是 v010 的候选卡，本版只在 `05-pending-decisions.md` 里登记。

## 5. 本版新增的可复用判据（写进记忆）

1. > **"某功能没实现"必须先 `grep` 全局符号，不能只看它"应该在"的文件。**（F-42 教训：功能会搬家）
2. > **说"全绿"前先 `cat package.json | grep verify`，核对每个数字真的来自那条命令。**（F-43 教训）
3. > **不在 `verify` 里的检查不是闸门，是个人习惯。个人习惯会在传接中消失。**（F-43）
4. > **派活前先读待改的那 3 行。** 派了两代规划还没落地的任务，要怀疑的是**任务描述本身**。（F-27 教训）
5. > **零运行时影响 + 不在闸门里 = 可以无限期存活。** 找出这类错误的唯一方法是补齐闸门，不是更努力地看。（F-46 教训）
6. > **管道 + `grep` 会吞掉上游退出码。** 任何"过滤后再判断"的门禁都是假闸门。
