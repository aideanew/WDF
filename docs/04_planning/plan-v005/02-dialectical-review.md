# 02 · 辩证复核

> 方法论：对 plan-v004 做双向 steelmanning（先尽量强地替它辩护，再尽量强地反驳它），最后取"合题"。
> 结论前置：**plan-v004 的 DAG 骨架与所有权思想保留，路径层与验收层整体重构。**

## 1. 正题（Thesis）——plan-v004 做对了什么

### 1.1 收敛能力：把"v1.0 剩余"从 20 张垃圾清单压到 8 张卡

plan-v002/v003 遗留项曾达 40+ 条（含优化、真机、备案、赶海整片）。plan-v004 果断按"是否阻塞 v1.0 可演示闭环"一刀切，只保留 8 张，并把赶海/钓鱼/聊天移入 v1.1。
**这一点必须继承**：范围蔓延是这类项目最大的隐性成本。

### 1.2 波次化：首次给出"可并行 / 必须串行"的显式判据

`06-tasks-and-dag.md` §6.2 明确写出"4007 与 4008 动不同视图组件 → 可并行；4009 动开锁 → 排后"。
**这一点必须继承**：并行安全判据是单助手串行模式下的效率来源。

### 1.3 所有权矩阵：把"谁能改哪"变成可检查的表格

`§6.3` 的四列矩阵，把跨界修改从"口头纪律"变成"可对照的清单"。这是 EXEC-BRIEF-0003 G-03 的表格化，方向正确。

### 1.4 真机降级判据：允许 UNKNOWN 而不允许伪造

4009/4010/4011 卡与 G-07 一致，明确"无真机记 UNKNOWN"。
**这一点是整个体系里最有价值的纪律**——它把"假装测过"这条路堵死了。

## 2. 反题（Antithesis）——plan-v004 的结构性失真

### 2.1 失真一：路径层全错（以"设想目录"代替"实际目录"）

| 卡 | plan-v004 假设路径 | 代码实际路径 | 后果 |
|---|---|---|---|
| 4007 | `features/merchant/view/` | `features/economy/view/MerchantPanel.ts` | 按卡找文件找不到；矩阵无法对照 |
| 4009 | `features/salvage/view/` | 目录存在但**只有 `SalvageView.ts` 空壳** | 无接缝可挂 |
| 4015 | `server/src/modules/save/service.ts` | `server/src/modules/account/service.ts` | **改错文件，改完毫无效果** |
| 4008 | `features/inventory/view/**` | 正确，但**需要连带改 `features/economy/model`** | 允许清单卡死实现 |

证据链：`01` §4.3 `E-12`、§5.1 `F-08`。

**这一条是致命的**：规划的价值在于"照做就能成"，路径错了等于把执行者推下悬崖。而且它有一个恶劣特性——**错误不会在执行时报错，只会在验收时表现为"改了但没用"**，导致执行者自我怀疑而非怀疑规划。

### 2.2 失真二：输入物缺失被当作"已具备"

`TASK-4009` 的输入写 `docs/03_solution/ui/screen-salvage.md`。实测：**该文件不存在**（`E-27`）。
`TASK-4008` 的输入 `screen-inventory.md` 存在（唯一幸存的 UI 文档）。

**反题成立**：一张"输入不存在"的卡，在 DAG 上却标注"阻塞条件：无"。这是把未知风险伪装成零风险。

### 2.3 失真三：数值可行性未做前置校验

`TASK-4009` 的核心断言是"遇到上锁箱子弹连点界面"。实测 `chests.csv` 三箱 `lock` 全为 `none`（`E-06`）。
**功能写完了也没有一个箱子会触发它**——这不是实现问题，是**数值层前置条件不成立**。

同时"降级掉 base_price 最低物品"按字面执行会掉 `item_0013`（`base_price=0`），等价于空手而归（`E-08`）。

**反题成立**：plan-v004 把"数值层可行性"当作已解决，实际只解决了"表里有数"，没解决"数能驱动这条路径"。

### 2.4 失真四：验收层只有"verify 绿"，没有"防假绿"

plan-v004 全系列卡的验证命令统一是 `npm run guard && npm test`。但 `01` §5.1 已证：**`features/**` 依赖 `'cc'`，Node 测不到**。于是：

- 4008/4009 是纯 UI 卡，`npm test` 对它们**零覆盖**；
- 卡一旦标"verify 绿"，读者会误以为 UI 被验证过。

**反题成立**：单一验收口径 + 不可测对象 = 制度性假绿。这也是 `BASIC-34`（`grep` 过滤式漏 `services/**`）教训的同类问题：**验证手段本身的正确性从未被验证**。

### 2.5 失真五：证据要求未分层

4007 已提交代码却无 `EVD-4007`（`E-25`）。plan-v004 定义了"证据路径"字段，但**没有定义证据的最小内容**，导致字段存在而目录为空，无人察觉。

## 3. 合题（Synthesis）——plan-v005 的扬弃

| 维度 | plan-v004（正） | 反题击中 | plan-v005（合） |
|---|---|---|---|
| 范围 | 8 张卡收口 v1.0 | 收敛正确，但漏了"止血"与"测试补强" | 保留 8 卡，**前置 W0 止血波 + 插入 W4 测试波**（10 张卡） |
| 路径 | 按设想目录写 | 4/8 路径错 | **所有权矩阵以 `find` 实测路径为准**（`04` §4.3），卡内路径必须能在仓库中 `ls` 到 |
| 输入 | 假定文档齐备 | 4009 输入不存在 | **开卡前置校验**：输入文档不存在 → 卡状态 `blocked`，不得进 DAG 可执行位 |
| 数值 | 表有数即视为可驱动 | chests 全 none / 保底价 0 | **新增"驱动性校验"层**：路径断言必须能被现有数值触发（`03` D-20/D-27） |
| 验收 | 统一 `guard && test` | UI 不可测 → 假绿 | **四参照系 + 分层验收矩阵**（`10`）：逻辑层单测 / 类型检查 / 守卫 / 证据 / 真机 UNKNOWN |
| 证据 | 有字段无内容标准 | EVD-4007 缺失 | **EVD 最小内容规范**（`10` §10.5）：命令、输出、时间、commit、判定五要素 |

**一句话合题**：
> 保留 plan-v004 的**范围和并行判据**，废弃它的**路径假设和单一验收口径**；把"完成"从一元布尔改造成**四参照系 + 可执行断言**，并把"规划本身是否正确"纳入可检验对象。

## 4. 四重相对性（"相对论"的具体落地）

> 任一结论只在特定参照系内成立。跨参照系搬运结论，是本项目历史上所有"假完成"的共同根因。

### 4.1 完成度的相对性：代码存在 ≠ 完成

参照系：`代码` / `闸门` / `证据` / `复现`。
4007 在「代码」参照系内 100%，在「证据」参照系内 0%。**报"4007 完成"是把一个参照系的结论搬到四个参照系上**。
落地：`01` §7 四参照系矩阵，任 ✗ 即整体 ✗。

### 4.2 路径正确性的相对性：文档路径相对"设想"，代码路径相对"现状"

`features/merchant/view/` 在**设计意图**的参照系里是对的（模块化清晰），在**当前代码**的参照系里是错的（4007 落到了 economy）。
**两者都不假**，但执行必须锚在后者。
落地：所有卡内路径以 `ls` 实测为准；`04` §4.3 矩阵标注"实测路径"列。

### 4.3 风险等级的相对性：不可观测的功能 = 最高风险

4009 在「代码复杂度」参照系里是中等；在「可观测性」参照系里是**最高**——因为 `lock=none` 意味着它**永远不会在真机上跑到**，bug 会潜伏到上线。
**同一个功能，在两个参照系里风险等级相反**。这正是"辩证"的实际用途：不能只按工作量排风险。
落地：`03` D-20 强制要求先解决"可触发"，再谈实现。

### 4.4 价值的相对性：数值口径决定玩家可感知性

"掉 base_price 最低物品"在**程序正确性**参照系里无懈可击（确实掉了）；在**玩家体验**参照系里是 0 价值（`base_price=0`）。
**技术正确 ≠ 体验正确**。
落地：`03` D-27 改为"按 `base_price ≥ 1 且 `recycle_bp` 非空"筛候选，取最低者"，并把口径写进契约注释。

## 5. 对 plan-v003 的连带复核（防止旧结论回潮）

| plan-v003 结论 | 现状复核 | 是否仍成立 |
