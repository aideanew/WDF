> ① **执行期**：每完成一步勾一次，防止"感觉做完了"；
> ② **复查期**：任何人可以用本文的检测命令**独立复核**，不依赖执行者的自述。

## 3. 反作弊清单（12 条，每条给检测命令）

> 每条都对应一件**本项目真实发生过或极易发生**的事。复查时逐条跑，不看执行者自述。

| # | 作弊形态 | 为什么能骗过人 | 检测命令 / 方法 |
|---|---|---|---|
| 1 | **假绿·过滤式错误** | tsc 输出里引擎错误噪音大，顺手 `grep 项目路径` 就"零错" | `grep -rn "grep.*client/assets" docs/ tools/` → 应为 0；统一用 `npm run check:types` |
| 2 | **假绿·改测试而非改实现** | 断言红了就改断言，测试立刻绿 | `git diff <commit> -- tests/` 与 `git diff <commit> -- 源码` 对照；只有 tests 变而无源码变 = 可疑 |
| 3 | **伪造真机** | EVD 里写"真机测试通过"，无人核查 | `grep -riE "实测\|真机" docs/06_validation/evidence/` 后逐条核对是否有录屏/截图文件 |
| 4 | **SIMULATED 冒充 MEASURED** | 模拟数值达标就写"命中率 52% 通过" | `grep -c "MEASURED" docs/06_validation/evidence/EVD-4011/hitrate.md` 且核对是否有真机 jsonl |
| 5 | **空 EVD** | 建了目录、写了"全部通过" | 每份 EVD 必须含 §3.5 五要素；`grep -L "## ⑤ 判定" docs/06_validation/evidence/*/README.md` → 应为空 |
| 6 | **UNKNOWN 写成 PASS** | 表单里只有 PASS/FAIL 两格 | `grep -rn "UNKNOWN" docs/06_validation/evidence/` 与 `current-plan §v1.0 已知局限` 交叉核对条数 |
| 7 | **数值写死** | UI 里直接写 `10000` 比读表快 | `grep -rnE "\b(10000|8500|13000)\b" client/assets/scripts/features/` → 应 0 命中（配置值只准从表读） |
| 8 | **手改 generated** | 改生成物比改源 + gen 快 | `npm run guard` 第 7 项；或 `git diff --stat client/assets/scripts/generated/` 后确认由 `npm run sync` 产生 |
| 9 | **跨所有权修改** | 顺手改了隔壁模块 | 按 `04` §3 矩阵逐文件核对 commit 的 `--name-only` |
| 10 | **契约加码不加映射** | `as any` 绕过 `satisfies` | `grep -rn "as any" packages/contracts/` → 应 0；`npm test -- --test-name-pattern="错误码"` 必绿 |
| 11 | **卡片划勾无提交** | 文档改状态最省事 | 每个标 done 的卡，`git log --grep="<卡号>"` 必须有提交 |
| 12 | **改了代码没改文档** | 文档滞后无人管 | `npm run gen:docs` 后 `git status` 若无变化才算索引同步；`current-plan`/`roadmap` 的数字须与实际 `npm test` 计数一致 |

### 3.1 一条"元规则"

> **任何"通过"的结论，必须能被一个不看解释的人用命令复现。**
> 不能复现的通过 = 未验证（不是"已验证但没写命令"）。

## 4. 本规划自身的可证伪点（自我怀疑清单）

> 一份不可被证伪的规划，等于不可信。以下是本规划里**可能出错**的判断，以及如何推翻它。

| # | 我的判断 | 可能怎么错 | 推翻方法 |
|---|---|---|---|

| 3 | 4015 只做了 2/6 步 | 若另外 4 步在别的分支/未推送提交里已做 | `git log --all --oneline -- server/src/modules/account/service.ts` + `git branch -a` |

**使用方式**：任何人发现上表某条判断错了，**不需要推翻整份规划**——只需修正对应条款，并在本表追加一行"已证伪 + 修正指向"。规划的健壮性来自"错得起"，而不是"不出错"。
