### 1.1 为什么不能"逐段修补"

`current-plan.md` 有 7 个大段，其中 5 段是 M1 时代（10-26）的内容，2 段是 plan-v002 时代的"事实基线"。逐段修补会产生一份**自相矛盾的缝合怪**（前一句说 107 测试，后一句说 158 测试）。

**正确做法**：**保留历史段不动**（它们记录了当时的判断，有价值），在文档**顶部插入新的"当前状态"段**，并给历史段加时间戳标记。

#### 2.1.5 `error-catalog.md`：补 `chest.open` 错误路径

在 `3002 QUOTA_EXHAUSTED` 之前或合适位置，追加开箱相关：

```markdown
| 1001 | BAD_PAYLOAD | CONTRACT | 开箱时背包无该箱 / `hitsUsed < hits_required` | 操作无效，请重试 | chest.open |
```

> 复用 1001 而非新增码：`chest.open` 的失败全部是"请求本身不合法"，无独立 UX 出口，不值得新增码（`2004` 的教训：新码必须有**独立出口**才值得解冻）。

#### 2.1.6 `glossary.md`：补 6 个术语

| 术语 | 定义 | 首次出现 |
|---|---|---|
| **影子账本**（ledger_entry） | 服务端只追加的资产流水；与客户端存档比对，容差 0，不一致返回 1001 | ADR-0012 |
| **幂等 rid** | 写动作的请求号；同一 `(playerId, rid)` 24h 内重放返回首次结果（只缓存成功） | MUST-07 / `scripts/4020` |
| **可达性** | 一条功能路径能否被真实玩家在现有数值下触发；不可达 ≠ 未实现 | plan-v005 `F-17` |
| **EVD 五要素** | 命令/输出/时间/commit/判定；缺一即无效证据 | plan-v005 `10` §3.5 |
| **MEASURED / SIMULATED** | 真机实测 / 模型推算；后者不得用于满足出口条件 | plan-v005 `11` §2 |
| **UNKNOWN** | 因环境缺失而未验证；必须写明"缺什么、何时补"，不得记 PASS | G-07 |
