# 02 · 需求基线复核

> 唯一需求源：`docs/01_product/design-source/我的筏-深度设计方案-v5.5.md` + `材料与工具总表.md` + `mvp-scope.md` §5。
> 本文件不复述 GDD，只做**可验证化改写**与**冲突检查**。

## 1. 一句话复述

玩家在筏上出钩打捞 → 用材料制作/扩筏 → 靠商人变现 → 打岛屿与塔防 → 每日一海进总收益榜；全程必须联网、服务端权威记账，微信小游戏首发。

## 5. 隐含要求（文档没写但执行必需）

| # | 隐含要求 | 不做的后果 |
|---|---|---|
| 1 | 开箱必须与存档同事务，否则并发双花 | 玩家同时点两次可开 2 次只扣 1 个 |
| 2 | 开箱发奖必须写 `ledger_entry` | 后续 `economy.sell` 影子账本容差 0 判不一致 |
| 3 | `chest.open` 必须校验"该 item 真的是箱子" | 任意 `itemId` 可被当作箱子开，任意物品可被消耗/复制 |
| 4 | 无存档时必须报错而非静默成功 | 客户端 `success:true` 但背包无变化，玩家认为吞道具 |
| 5 | 合规材料里的每个"已完成"都要能指到代码行 | 提交审核时被抽查即穿帮 |
| 6 | 所有产出必须进版本库 | 未提交 = 下一个人看不见 = 重复劳动 |
