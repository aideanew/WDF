## 3. 并行判定（机械规则，逐条给依据）

判定式：**可并行 ⟺ 无共享可变状态 ∧ 依赖契约已冻结 ∧ 文件所有权不相交 ∧ 不共用迁移版本号**

| 组 | 卡 | 可并行？ | 四条逐一核对 |
|---|---|---|---|
| **G1** | 5001 ∥ 5002 | ✅ **可并行** | ①`MerchantPanel.ts` vs `chest/service.ts` 无共享状态 ②都基于已冻结契约（5002 用既有 `ERR.BAD_PAYLOAD`，不新增码）③路径不相交 ④本次无迁移 |
| **G2** | 5008 ∥ 5009 ∥ 5010 | ✅ **可并行** | ①分属 `tests/`、`docs/07_release/`、`docs/05_execution/` ②契约已冻结 ③路径不相交 ④无迁移 |
| **G3** | 5004 ∥ 5005 | ❌ **串行** | 共享 `chest/service.ts`，违条件①③ |
| **G4** | 5005 ∥ 5006 | ❌ **串行** | 同上 + 5006 需 B-1 裁决 |
| **G5** | 5007 ∥ 5004 | ❌ **串行** | 5007 消费 5004 定的响应形状，违条件② |
| **G6** | 5006 ∥ 5007 | ✅ **部分可并行** | UI 骨架可先用 mock 数据做，但**接线必须等 5006**。建议 5007 的"锁图标与点击手感"先做，"接真接口"排后 |
| **G7** | 5011 ∥ 任意 | ❌ **最后做** | 依赖全部完成 |

**同时最多 2 个写 Agent**（5001/5002 这组只有 2 张，符合）。

## 5. 档位分配

> 用户环境的可用档位为 `lite`（快/省）/ 默认 / `reasoning`（强）。下表按"不可逆性 × 影响范围"分配。

| 卡 | 档位 | 理由 | 升级条件 |
|---|---|---|---|
| 5001 | `lite` | 1 行类型断言，无设计决策 | 若发现 `SellPayload` 本身定义错 → 升 `reasoning` |
| 5002 | `lite` | 替换常量 + 删导入 | 若决定新增 3003 → 升 `reasoning`（要动契约） |
| **5004** | **`reasoning`** | 事务边界 + 账本一致性，错一次要回滚存档 | 连续 2 次失败 → 停手重写任务书 |
| 5005 | 默认 | 加一次查表校验 | 若 `chests` 表需扩展字段 → 升 |
| **5006** | **`reasoning`** | 开锁数值规则 + 反作弊（客户端不可信） | 同 5004 |
| **5007** | **`reasoning`** | UI 设计（用户明确要求自己做），且 `'cc'` 代码无自动化测试兜底 | — |

| 5009 | 默认 | 涉及事实判断（哪些"已完成"能写），需读代码 | 若发现更多虚假陈述 → 升 |

## 6. 熔断规则

```
同一卡连续 2 次验收失败 → 停止改代码
  → 三选一：重写任务书 / 升档 / 标 blocked
禁止换提示词硬撞第 3 次
```

**本规划的额外熔断**（针对本项目历史事故）：

| 触发 | 动作 |
|---|---|
| 发现工作树被外部同时写入同一文件 | **立即停手**，在 `plan-v008` 追加漂移记录，等归属确认 |
| 改动后 `npm test` 从绿变红且原因不明 | 回滚本次改动，不叠加 |
| 发现规划与代码冲突 | 以代码为准 + 记录差异，不静默改规划 |
