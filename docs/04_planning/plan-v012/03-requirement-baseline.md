# 03 · 需求基线复核

## 1. 复述与拆解

**一段话**：这是一个微信小游戏《我的筏不可能这么大》——玩家在海上用小游戏式的"弧形力度条出钩"打捞漂浮物，
拿材料在船上合成、建房间、扩筏提高浮力以捞更多；随后驶出浅海进入深海做五项玩法（抢野人船、石油、沉船、
探索、钓鱼）、占岛建基地、抵御野人袭击；靠商人回收变现，靠榜单与称号获得长期目标。**必须联网**，
存档以服务器为准，10 年前手机（2 核 4G）能跑。

| 维度 | 内容 |
|---|---|
| 用户 | 微信小游戏玩家（个人主体上架，纯广告变现）；后续抖音（软著下证后） |
| 管理端 | **不做界面**（D-01）：区服管理与封号只有脚本 + SQL（`server/src/modules/ops/`） |
| 系统边界 | 端 = Cocos 3.8.8 客户端（微信/抖音/H5）+ Fastify 5 服务端（PGlite）+ `game-core` 纯规则 + `contracts` 契约源 + `game-data` 数值源 |
| 来源锚 | `mvp-scope.md`（PRD-0004，§1 核心工作 / §2 模块×周次 / §5 v1.0-v1.1 分期）+ 设计源 v5.5 + `decision-index.json` |

**关于"来源需求"编号**：`docs/02_requirements/features/` **没有任何 REQ-F 文件**（I-11）。
本版每张卡的来源统一用三段式：`mvp-scope.md §x` + `设计源 v5.5 §y` + `D-zz`。

## 3. 冲突清单（不静默替用户决定）

### 3.1 ★ C-1：v1.0 的范围有两套互不兼容的定义（**本版最严重的冲突**）

| 依据 | v1.0 必须含 | 时间 / 权威 |
|---|---|---|
| `mvp-scope.md` §5（PRD-0004，`status: active`） | 出钩+捞做扩；浅海+深海、等级 49；房间；7 员工岗位；自己的岛；野人岛+迷宫塔防+回放；3 兵种；每日一海；称号；总收益榜+省份榜；商人回收；激励视频；实名/防沉迷/隐私；必须联网；区服管理（脚本） | 2026-10-23「已定·Hark代定」 |
| `D-50`（`DECIDED`） | 把 `progression / crew / power / ads / leaderboard / event / island / defense / social / fishing / salvage / compliance / telemetry` **13 个模块延期到 v1.1** | 2026-10-28 用户拍板 |

**两者都自称"已定"，且直接覆盖。** 我按两种口径各算一次完成度（**这两个数字都不能单独使用**）：

| 口径 | 计量 | 完成 | 完成度 |
|---|---|---|---|
| **A. 按 `mvp-scope §5` 的 v1.0 清单（16 项）** | 出钩✅ / 捞做扩❌ / 等级49❌ / 房间❌ / 7员工❌ / 岛❌ / 塔防❌ / 3兵种❌ / 每日一海❌ / 称号❌ / 榜单✅ / 商人✅ / 激励视频(client)❌ / 合规(client)❌ / 必须联网✅ / 区服脚本✅ | 6 / 16 | **37.5%** |
| **B. 按 `D-50` 的定义（23 个 v1 模块）** | 六层齐全 6 个 + settings 基本齐 + leaderboard 部分 = **8 个** | 8 / 23 | **34.8%** |

**有意思的是两者几乎相同**（37.5% vs 34.8%）——因为它们描述的是同一批欠账，只是切法不同。
所以这个冲突**不改变工作量**，只改变**"什么时候能宣称 v1.0 完成"**。

**处置**：不替你决定。登记 **D-59（PROPOSED）**：`v1.0 的完成判据以 D-50 为准（窄口径，先上线）` 还是
`以 mvp-scope §5 为准（宽口径，一次做完）`。**二者都需要，区别只是发布节奏**，见 `10 §1`。

### 3.2 C-2：6 张空表的 BLOCKED 是否成立

### 3.3 C-3：`explore` / `limits` / `phrases` 三张表要不要保留

三张都 **0 消费方 + 设计源无条目**。按 `§13.13`「不得为凑数伪造方案」与 `AGENTS.md:34`「不新增 `*_old`」，

**不阻塞任何卡。**

### 3.4 C-4：「必须联网」vs 「弱网可玩」

设计源 §11.3 已作废"断网也能玩"，改为必须联网（ADR-0008）。`RpcClient.ts:22` `FORCE_OFFLINE = false` ✅。
**但** `MOCK_HANDLERS`（`RpcClient.ts:177-190`）仍在：网络失败时 `compliance.check` 返回
`{verified: true, minor: false}`——**合规恒真**。这是生产风险，登记为 R-6（`10 §2`），本版不改（属业务代码）。

### 3.5 C-5：`telemetry` / `account` 被标 `client: true` 但可能不需要界面

`module-catalog.json` 给 23 个 v1 模块全标 `client: true`，导致"客户端空壳"被一律判为缺陷。
实际：`telemetry` 是埋点（只需在关键点调 `telemetry.track`，无需独立面板）；`account` 的绑定 UI 属 v1.1。
**处置**：登记 I-10；`06 §4` 的"六层齐全"判据对这两模块按"**有调用点即可，不要求独立面板**"。
