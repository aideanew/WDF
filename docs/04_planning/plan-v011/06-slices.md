# 06 · 垂直切片清单

## 1. 切片的定义（本版口径）

切片 = **端到端的一刀**，不是技术层。本项目已有可运行的步行骨架（登录 → 主界面 6 Tab → 存档 → 云同步），
所以 **§5.3 的"第一刀必须是步行骨架"在本版已由历史满足**（`TASK-3101` + `M1 闭环`，`current-plan.md:80-86`）。
本版的第一刀直接落在"给骨架多长一个可演示的行为"。

## 3. 排序理由（为什么是这个顺序，不是别的）

| 排序决定 | 理由（可反驳我才改） |
|---|---|
| **A 在 B/C 之前** | ① v1.1 以 v1.0 上线为前提（`mvp-scope.md:62`）；② A 是**口径欠账**不是新功能，拖着不补，v1.0 永远无法被诚实称为完成（`02 §4`）。 |
| **SA-1 内部：数据(01) → 规则(02) → UI(03)** | 浮力口径未定就写 UI，UI 必然返工。PD7-01 的前半（口径落账）是唯一真正的阻塞点，且它是**半天**的活。 |
| **SA-2（拒绝态）紧跟 SA-1，不并到 SA-1** | 并入会让 SA-1 验收标准超过 6 条（§6.3 过大信号）；且 SA-2 触及 `3101` 与 `toUxState` 的既有语义，独立成刀才好判定。 |
| **SA-3（海域）放 A 段末尾** | 它消费 `services/time`（空壳），是 SHOULD 项，不影响五环成立 → 优先级低于 SA-1/SA-2，但比 B 阶段轻，插空做。 |
| **B 全部在 C 之前** | 13 个 v1.1 模块里 11 个的第一阻塞点是表 0 行（`02 §1.7` + `plan-v010/02 §2.1`）。先写代码=再造一批占位实现。 |
| **B 内部：成长(06) → 生产(07) → 战斗(08) → 玩法(09)** | 解锁链是**依赖根**：`unlocks/levels` 不给，`crew` 的岗位解锁、`island` 的建筑解锁、`event` 的入场条件全都无参可依。战斗簇最重放后面，避免它拖住其他三簇。 |
| **C 内部：10 → 11 → 12 → 13 → 14 → 15 → 16** | ① 10（等级）是 11/13/14 的前置（解锁条件）；② 12（广告）依赖 11（离线结算）与「商店」，而商店=`economy.buyQuota` 需要 `limits` 表（SB-4）；③ 15（塔防）最重、允许降级，放最后以免阻塞其他；④ 16 是三条互不相干的轻玩法，可作填充/并行位。 |
| **SD-1 独立成段** | 它 100% 挂在外部资质（D-51），排进 C 只会制造"看起来在等"的假阻塞。 |

## 5. 关于 §5.2「每刀都能独立演示」的一处**诚实的偏离**

**B 阶段的 4 刀不满足"可演示给玩家"的标准。** 它们是**前置条件切片**，产出是数据表而非行为。

| 项 | 说明 |
|---|---|
| 偏离事实 | SB-1~SB-4 结束后，玩家看不到任何新东西 |
| 为什么仍然这样切 | 若把数据与展示强行合并，每刀会横跨 3 个以上模块（数据 + core + client），违反 §6.3 的"过大信号"，且 B 阶段的最大风险恰好是"数据来源没有"，不是"接口接不上" |
| 补偿措施（替代"可演示"） | 每张 B 卡必须产出一个**机器可判定的产物**：`placeholders.mjs` 前后对比 + 一条新增断言测试 + 一份"来源清单"（哪个字段取自哪份文档哪一行） |
| 谁来判定 | 独立验证者只跑 `npm run placeholders` + 定向测试，输出 PASS/FAIL/UNKNOWN，不读卡面自述（`08 §5`） |
