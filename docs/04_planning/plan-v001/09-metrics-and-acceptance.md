## 9.2 完成的定义（DoD）

一个 AT 只有同时满足以下 6 条才算完成：

1. diff **全部落在本 AT 所有权路径内**（对照 08）；
2. 验收标准**逐条有结果**（PASS/FAIL/UNKNOWN，不得写"基本满足"）；
3. `npm run verify` **全部通过**（gen + 9 项 guard + 10 项测试）；
4. 证据存 `docs/06_validation/evidence/EVD-<AT号>/`，**一周后的人能照证据复现**（含命令、输出、截图/录屏）；
5. **未修改任何冻结契约**（03）；
6. 需人工确认项（手感、真机）**已由用户确认**，并留确认记录。

## 9.3 验收执行方式

| 类型 | 谁验 | 产出 |
|---|---|---|
| 自动化（单测/集成/守卫） | 执行者跑，**独立验证者复核** | 命令 + 原始输出 |
| 手感/可玩性 | **用户亲自** | 录屏 + 一句话结论 |
| 真机（包体/帧率/断网/切后台/杀进程） | 用户在微信开发者工具 + 真机 | 截图 + 机型 + 系统版本 |
| 数值正确性 | 独立验证者对照 `design-source` 原文 | 差异清单 |

## 9.4 防自证循环

- 验收阈值**在规划阶段定死**（本节）；执行阶段**不得**下调。
- 执行者**不得**自己宣布 PASS；只能提交证据。
- 独立验证者只输出三值：`PASS` / `FAIL` / `UNKNOWN`；`UNKNOWN` 不等于通过。
- **反例（已经发生过的自证陷阱）**：`npm test` 10 项全绿，但 20 个服务端 handler 全为占位（问题 C10）。因此：**"verify 全绿"不是完成证明**，只是必要条件。
