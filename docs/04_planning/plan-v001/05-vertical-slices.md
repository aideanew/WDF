# 05 垂直切片

> 切片原则：按**端到端可演示的行为**切，不按前端/后端分层切。每刀 0.5–2 天可演示；<2 小时的并入相邻刀。
> 排序原则：① 第一刀必须是步行骨架；② 第二刀必须是**出钩手感（C1）**，不达标不扩展；③ 再"捞—做—扩"；④ 之后按 v5.5 11.4 周次；⑤ 不确定性高的先做（塔防寻路与回放、离线/联网同步、微信真机包体）。
> "可并行"判定见 07-dag；本节只标**意愿上的**并行可能，最终以 07 四条判据为准。

## 5.1 S0 · Cocos 工程初始化（【人工】）

**为什么必须单独成刀**：`client/` 下 `.meta`/`.scene`/`.prefab` 均为 0，`client/settings/` 只有 README（见 01-A5/C11）。没有工程就没有任何可演示的东西。

**人的操作（大白话）**：
1. 打开 Cocos Dashboard → 新建项目 → 选 **Empty (3D)** 或 **Empty (2D)** → 路径选 `e:\Demo\WDF\client` → 创建（Cocos 会自动生成 `settings/`、`package.json`、`.meta`）。
2. 编辑器里把设计分辨率设为竖屏 720×1280，适配 `Fit Height`。
3. 在 `assets/scenes/` 下新建场景命名 `Boot.scene`，保存。
4. 在 `assets/bundles/` 下依次新建文件夹并**在检查器里勾选"配置为 Bundle"**：`b-common`、`b-shallow`、`b-deep`、`b-island`、`b-defense`、`b-event`、`b-social`（Bundle 名与文件夹名一致；**不要**用 `main`/`resources`/`internal`/`start-scene`）。
5. 把 `Boot.scene` 拖进"构建发布"的**起始场景**。

**验收**：`(Get-ChildItem -Recurse client -Filter *.meta).Count` > 0，且 `client/settings/` 出现 `project.json`；在 Cocos 里点"预览"能看到空白场景。

## 5.2 S1 · 步行骨架（第一刀，必须最先）

**演示脚本（照着做一遍就算通过）**：

```
① 启动 → Boot 场景 → 显示"合规状态"
② 长按出钩（此阶段可以是"点一下就出钩"的临时版本，S2 再打磨）→ 钩回一件物品
③ 背包 +1，写入本地存档（SaveFile 封存，含 checksum）
④ 杀掉进程 → 重新启动 → 物品还在（读档 + 校验和通过）
⑤ 联网 → 调用一次 save.push（带 token、带 rid）→ 服务器写 save_snapshot 一行
⑥ 故意发一个非法请求 → 收到统一错误封套（c != 0 + msg）
```

**这一刀要打通的真实链路**：

| 段 | 要做的最小实现 | 文件所有权 |
|---|---|---|
| Boot 场景 | `Boot.scene` + `BootController` 挂载 | Agent-Client |
| 合规状态 | `compliance.check` 真实 handler（可先返回 `verified=true`） | Agent-Server |
| 鉴权 | `account.login` 真实签发 token（可用本地 HMAC 占位） | Agent-Server |
| 出钩（临时） | `HookModel.cast()` 直线出手、命中即取 | **Agent-Core（我）** |
| 物品数据 | `items.csv` 填 **1 条** + `raft_tiles` 1 条；跑 `npm run gen` | Agent-Data |
| 本地存档 | `SaveFile` 序列化/反序列化/校验（`save/schema.ts` 已有函数，接起来） | Agent-Core |
| 云存档 | `save.push` 真实写入 `save_snapshot`；`baseRevision` 校验 | Agent-Server |
| 数据库 | 执行 `0001_init.sql` 到本地 PostgreSQL | Agent-Data + 用户 |
| 错误封套 | 前端统一 `RpcClient` 解析 `c != 0` 并 toast | Agent-Client |

**验收（可自动化的部分）**：
- 集成测试：`node --test tests/integration/skeleton.test.mjs` → 登录 → push → pull → 断言 revision 递增、checksum 一致。
- 手工：照上面 6 步走一遍，录屏存 `docs/06_validation/evidence/EVD-0001/`。

## 5.3 S2 · 出钩手感（C1 闸门，不达标不扩展）

**为什么第二刀**：`mvp-scope.md` 的 C1 是本项目唯一的核心验证点；`HookModel` 与 `HookView` 当前是空壳（01-A5-2/A5-3）。

**要实现的规则（进 `game-core/hook`）**：
- 蓄力：长按时间映射到 `powerBp`（0–10000bp）；力度条 **往返约 1.2 秒**（v5.5 4.3 已定）。
- 出手：给定 `powerBp` + 角度 → 钩子沿轨迹飞行，触及目标距离判定命中。
- 判定：`game-core` 只输出**确定性结果**（不碰渲染、不碰 `Date.now`，时间由调用方传入）。
- 绳子承重：细绳/粗绳/钢缆三档（材料表六章）；超过承重的箱子"拉到半路脱钩"（赶海规则 5，日常可先不启用，见 U-05）。

**必须现场测量的指标**（这是 S2 的交付物之一）：
| 指标 | 目标 | 测量方式 |
|---|---|---|
| 首钩命中率 | ≥45% | 埋点 `hook.hit`/`hook.miss`，自己连打 30 钩 |
| 前 10 钩成功率 | 40%–60% | 同上，前 10 钩子集 |
| 出钩到回手耗时 | ≤3s（空钩） | 埋点时间差 |

**闸门规则**：三项任一未达 → **停止扩展**，回到力度曲线/判定半径调参；由用户亲自确认手感。

## 5.5 S5–S10 · 闭环与上线

- **S5** 存档冲突：造两个客户端改同一档 → 后到者拿 `conflict` → `resolveFork` 二选一；校验和改一位 → 判定损坏 → 走云端档；
- **S6** 经济：回收价 `×50%`、区域浮动 ±30%、`daily_quota`（**注意 D-02 语义冲突，需裁决**）；
- **S7** 开锁：`chest` 的原子规则已有（`LOCK_HITS`/`isHit`），补"一局状态机 + 工具消耗 + 失败不重置"；

## 5.6 S11 · 塔防与回放（不确定性最高）

**为什么提前做技术验证**：v5.5 11.4 把它放第 4 周，但它是唯一"做不完就没有兜底"的模块。项目记忆里已写兜底："若不稳，先退化为离线文本结算，后续再加回放"。

**技术验证内容（2 天，独立于美术）**：
1. `defense/distanceField` 已有 → 造 20×20 网格、3 个入口、1 个城门 → 断言全入口可达（已有单测，扩展到真实地图）。
2. 固定步长 10Hz 模拟：一波 40 敌人、4 座塔 → 跑 1000 步 → 记录状态哈希。
3. 回放：把"种子 + 操作序列"重放 → 断言状态哈希一致。
4. 性能：40 敌人 + 60 投射物在 2 核 4G 上是否 30 帧（**必须真机**）。

**兜底**：验证失败 → 塔防降级为"离线文本结算"，回放延后到 v1.2。
