# 02 需求基线复核

> 权威顺序：`设计要点记录.md`（时间最新者胜） > `我的筏-深度设计方案-v5.5.md` > 其他草案。
> 本文只做**整理与判定**，不替用户决策；所有建议显式标【建议】。

## 3.1 核心问题复述（一段话）

玩家是**单机感很强的生存+打捞玩家**：从一块木筏起步，长按蓄力**出钩**捞漂浮物与箱子，靠"捞—做—扩"循环把筏变大、造设施、雇员工、上岛、建防御，并在每天 20:00–21:00 的**赶海**里与其他玩家比谁 3 分钟捞得更值钱。
管理员是**运营方（当前就是用户本人）**：负责**开新区**（新玩家进最新开放的区服）、**封号**、**改配置**（数值表热更、活动开关）、查看风控与排行榜复核结果。
系统边界：客户端只负责**表现与输入**，所有写操作必须由服务器确认（ADR-0008 必须联网）；服务器是权威，负责结算、发种子、风控、榜单；`packages/game-core` 是前后端共用的**确定性规则**，`packages/contracts` 是唯一接口契约；数值表是唯一数值源。**系统不包含**：PVP、交易、招募、埋葬、远洋（第二版，只登记不建目录不建表）。

## 3.2 需求分级

分级口径：MUST = v1.0 不做就不能上线；SHOULD = v1.0 能做则做、可在 v1.1 补；COULD = 有余力再做；MUST NOT = 首版明确禁止。

### 3.2.1 MUST（每条改写成可验证句）

| 编号 | 需求 | 可验证句（验收时照此判定） |
|---|---|---|
| MUST-01 | 出钩手感 | 在 Boot 场景后可**长按蓄力、松手发射**；力度条一个往返约 1.2 秒（±20%）；单次出钩从松手到钩子回到手上 ≤3 秒（浅海空钩）；钩子与漂浮物碰撞判定生效。**首钩命中率 ≥45%、前 10 钩成功率 40%–60%**（见 09） |
| MUST-02 | 漂浮物与箱子生成 | 浅海场景按潮汐周期（6h 一轮、持续 10min）刷新漂浮物；同屏漂浮物 ≤20；出箱率按 `箱子与沉船概率-草案.md` 已定档位（不上锁 2% / 铁 1% / 铜 0.5% / 银 0.1% / 金 0.001%），且**空箱率为 0**（每钩必中一个箱子，见赶海规则）——**两条规则的适用范围需裁决，见 U-05** |
| MUST-03 | 捞取入包 | 钩到的物品进入背包，重量累加；背包/货舱超容时给出明确提示而非静默丢弃 |
| MUST-04 | 浮力约束 | 任意时刻 `总浮力 ≥ 总重量`；扩建/装载导致超重时拒绝并提示"浮力不足，还差 X"（`raft/checkChange` 已有规则，需接 UI） |
| MUST-05 | 本地存档 | 写入符合 `SaveFile`（schemaVersion=1、configVersion、saveId、revision、savedAt、modules、checksum）；**杀进程重启后能恢复到最近一次成功保存的状态**；校验和不符时判定为损坏并走降级流程 |
| MUST-06 | 必须联网 | 所有写操作走 `POST /v1/rpc`（或 `/v1/batch`），服务器确认后才落本地；断网时进**只读模式**并显示断网态；不静默排队写操作（ADR-0008） |
| MUST-07 | 幂等 | 带 `idempotent=true` 的动作必须携带 `rid`；同一 `rid` 重复提交返回首次结果，不产生二次副作用（`idempotency` 表 + `DUPLICATE_REQUEST 3001`） |
| MUST-08 | 鉴权 | 除 `account.login`、`compliance.check`、`config.manifest`、`telemetry.track` 外，其余动作未登录一律 `NOT_LOGGED_IN 2001`；令牌过期返回 `SESSION_EXPIRED 2002` |
| MUST-09 | 客户端版本闸 | `cv` 低于服务端最低版本返回 `CLIENT_TOO_OLD 9001`，前端弹出不可关闭的更新提示 |
| MUST-10 | 配置热更 | 客户端启动先调 `config.manifest`，`configVersion` 不一致则拉取新数值（`config_release` 表）；只热更数据不热更代码 |
| MUST-11 | 等级解锁 | 等级 1→49 按 `等级解锁表-草案.md` 12 段解锁；未达等级的物品/配方显示为锁定并写明所需等级；解锁链路无环 |
| MUST-12 | 合成 | 至少实现基础材料层（木板/木棍/细绳/粗绳/帆布/铁钉等）与基础工具层（抓钩/鱼竿/锤子/斧头/镐等）；配方最多 3 种材料；缺中间材料时提供"自动合成"；缺设施/员工时按钮置灰并写明原因 |
| MUST-13 | 开锁 | 4 档锁（铁/铜/银/金）；命中区按已定 20/15/10/5%；连中需求 1/2/3/4；失败**不重置进度**；工具用一次断一根（经济参数 30/150/600） |
| MUST-14 | 赶海（每日一海） | 每天 20:00–21:00 开放，每人一次、3 分钟；全服同种子；21:00 后不可进；21:05 结算；榜单前 10 有奖；计分口径见 U-03 |
| MUST-15 | 排行榜（总收益） | 按"已存入/已出售的有效价值"计分；丢弃与损坏不计分；按小时理论上限复核，超限进人工复核（`REVIEW_PENDING 5001`） |
| MUST-16 | 合规 | 启动先取 `compliance.check`（实名/未成年/时长/版号状态）；未成年按 `MINOR_TIME_LIMIT 2101` 限时；隐私政策与概率公示可访问 |
| MUST-17 | 包体 | 微信主包 ≤4MB；双平台共同预算 20MB；Asset Bundle 只装资源，脚本全在主包（ADR-0006） |
| MUST-18 | 帧率 | 中配 2 核 4G 安卓机锁 30 帧保持稳定（帧时间抖动在验收阈值内，见 09）；同屏漂浮物 ≤20、单界面节点 ≤300、DrawCall ≤40 |
| MUST-19 | 存档体积 | 单档 ≤300KB |
| MUST-20 | 管理员能力 | 管理员可**开新区**、**封号**、**改配置**；玩家端令牌不得调用任何管理动作（管理动作与玩家动作分属不同鉴权域） |

> 改写不了的：MUST-20 中"管理员"目前**没有任何载体**（无动作、无表、无界面），无法写成可执行验收句 → 计入 U-06（BLOCKING）。

### 3.2.5 v1.0 / v1.1 拆分【建议】

> 【建议】以下仅为建议，**不是已定**。依据 `立项评审-Hark回答.md` 第四节 + 10-23 10:45 已定清单。

| 归属 | 内容 | 理由 |
|---|---|---|
| **v1.0（5 周）** | MUST-01~19 全套 + 开新区的最小管理能力（仅"开新区 + 封号"两个命令，无界面，用脚本/SQL） | C1 出钩手感是唯一核心验证点；无合规与包体不能上线 |
| **v1.0 可选（若有余力）** | SHOULD-01（只做钓鱼）、SHOULD-02（商人只做回收） | 经济闭环的最小版本 |
| **v1.1（上线后 2–4 周）** | SHOULD-03 聊天、SHOULD-04 称号、SHOULD-06 沉船、SHOULD-08 员工、赶海排名分组与奖励发放的完整版 | 不影响核心验证，可后补 |
| **v1.2 / 第二版** | SHOULD-05 岛屿+塔防+回放、COULD 全部、PVP/交易等 | 工作量与风险最高；塔防回放是"不确定性最高"项，须先做技术验证 |

**建议的取舍（标【建议】）**：v1.0 把**塔防与岛屿整体移出**，只保留 `defense` 的寻路单测与数据表；否则 5 周内无法完成"可玩+可测+可上线"。

## 3.3 冲突检查

### 冲突 T-01：「总收益榜保留，刷榜严重时禁止离线」 vs 「断网也能玩主线」

- **文档侧**：v5.5 第十二章保留总收益榜；早期兜底方案写"刷榜严重时禁止离线"；同时项目章程写"断网也能玩主线"。
- **代码侧**：ADR-0008 已 `accepted`「**必须联网**」，`offline-sync.md` 已被该 ADR 约束。
- **判定**：ADR-0008 时间（10-23 10:40，拍板4 选 B）晚于早期兜底方案，**按"时间最新者胜"已事实上关闭此冲突**：不做离线玩法，因此不存在"禁止离线"这个兜底开关。
- **残留风险**：ADR-0008 与"断网也能玩主线"的原始诉求相反，属于**用户已知的主动取舍**，不重复列为待裁决。**状态：已确认（按 ADR-0008）**。

### 冲突 T-02：「9 个兵种全做」 vs 「5 周工期 + 拆 v1.0」

- **文档侧**：10-23 拍板 3 明确"维持原设计兵种不变（9 个全做）"；同一天 10:45 代定 v1.0/v1.1 拆分。
- **事实侧**：塔防本身在 v1.0 建议中已被移出；9 个兵种依赖岛屿、兵营、资源链，全部在塔防之上。
- **判定**：两者**不构成逻辑矛盾**（9 兵种是总量目标，v1.0/v1.1 是分期），但**排期上矛盾**：若 9 兵种都在 v1.0，5 周不可能。
- **处置**：按 10-23 10:45 已定"v1.0 3 个兵种、合计 9 个"执行。**状态：已确认**（数量已定），**残留分叉**：具体是哪 3 个（U-02）。

### 冲突 T-03：赶海计分是否含"箱子本身"

- 10-22 已定 10-6："计分细则：箱子本身原价计入"。
- 10-23 10:45："按每件捆到的物品价格相加"（未提箱子）。
- 时间上 10-23 更晚，但**该条是对"赶海奖品/规则"的复述，不是对计分口径的显式覆盖**，语义上不足以判定"取消箱子计分"。
- **判定**：**证据不足**，列入 U-03，需用户一句话裁决。

### 冲突 T-04：称号系统掉版

- v5.5 11.1【已定】（10-22）"称号系统首版就做"。
- 10-23 10:45 v1.0 清单**不含称号**，v1.1 清单**也不含**。
- **判定**：按"时间最新者胜"，称号被移出 v1.0；但**没有任何文件把它放进 v1.1** → 功能掉版。列入 U-01。

### 冲突 T-05：赶海跨期重复

- v1.0 清单含"每日一海"；v1.1 清单含"赶海多捞哦活动 + 赶海排名"。
- 术语表：赶海 = 每日一海 = 赶海多捞哦，**同一活动**。
- **判定**：同一功能被拆到两期，措辞不一致。列入 U-04（需明确 v1.0 做完整版还是仅做"能进能捞"）。

### 冲突 T-06：首版功能的"未列即删除？"

- v5.5 11.1【已定】首版含：商人/价格表/回收、钓鱼、区服聊天+世界频道、保护卡。
- 10-23 10:45 v1.0 清单**均未提**。
- **判定**：无法区分"遗漏"还是"有意移出"。列入 U-07（一次裁决四项）。

### 冲突 T-07：文档内周次自相矛盾

- v5.5 11.4 排期表第 4 周含"称号、每日一海"，同节后文又说第 5 周做；
- `mvp-scope.md` 周次表第 5 周有"称号系统"，第 5 节 v1.0 清单无称号。
- **判定**：**存在缺陷**，需返工文档（在 10-risks-and-decisions 里登记为 DOC-FIX 任务，不属阶段 A 业务代码）。
