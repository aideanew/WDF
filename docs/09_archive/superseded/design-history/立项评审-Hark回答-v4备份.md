## 一、先说结论：十大优先问题

| # | 问题 | 判断 | 推荐 |
|---|---|---|---|
| 1 | 一个人 5 周做完一期 | **做不完**。一期有十几个系统，光塔防 + 9 兵种 + 回放就要 1–2 周 | 拆成“上线版 v1.0（5 周）+ v1.1（上线后 2–3 周）”，见第四节。**5 周的目标是“可玩、可测、可提审”，正式上线是另一个里程碑**，看手续和审核 |
| 2 | 上线手续比开发还慢 | 微信官方：纯广告小游戏发布流程**预计 13–37 个工作日**（约 3–8 周），可与开发并行。微信纯广告游戏**一般不用软著**（只有名字含英文或“软件”、或涉及品牌合作才要）；**抖音要求游戏名和软著完全一致，所以上抖音必须有软著** | **本周就开始**：定主体、注册微信小游戏账号、定游戏名（纯中文、不带“软件”）；软著同步申请，给抖音用 |
| 3 | 断网可玩 vs 排行榜防刷 | 本地存档一定能被改，客户端上报的“总价值”不可信 | 榜单只放**服务器能复算**的数据；主线可以离线，但不直接进竞争榜 |
| 4 | 后端没定 | 榜单、赶海、离线袭击、存档找回都要服务器 | **一套后端服务两个平台**（云函数 + 云数据库 + Redis 排行），不各用一套平台云 |
| 5 | 双平台同步首发 + 账号 | 两平台登录、广告、审核、包体各不相同，同步首发等于联调和提审做两遍 | 两端代码同时开发、同时测，**正式发布分批**：微信先上，抖音错峰 2–4 周（拍板 7）。账号按已定规则：未绑定不互通，绑定微信 + 抖音即同一账号 |
| 6 | 主体：个人还是企业 | 影响版号、聊天、广告收款，需核实最新规则 | **拍板 1** |
| 7 | 聊天 | 自由打字要做内容审核、举报、未成年人保护；个人主体可能开不了（需核实） | 首版只做**快捷短语 + 表情**，不开自由打字 |
| 8 | 美术来源 | 方案里几乎没有美术规划，一人开发最容易卡在这 | 先定画风 + 买一套风格统一的素材包打底，AI 生成只做补充且要人工修 |
| 9 | 数值总表 | 浮力/重量、兵种、耗电、经验、金币产出都没表 | 建一张 Excel 总表，导出 JSON，改数值不改代码 |
| 10 | 防沉迷时间正好撞活动 | 未成年人法定只能在周五、六、日和节假日 20:00–21:00 玩 1 小时，**正好是赶海时间** | 不是坏事：未成年人那 1 小时刚好能参加赶海；但工作日他们进不来，榜单要接受这点 |

## 三、核心架构（推荐方案）

### 3.1 客户端分四层

```
玩法表现层   界面、动画、特效、音效（只管“看起来”）
玩法逻辑层   出钩判定、制作、船体浮力、员工、电力、塔防模拟、开锁、经济（纯 TypeScript，不碰引擎）
核心框架层   存档、配置表、事件总线、时间校准、随机数、资源与分包、对象池、UI 管理
平台适配层   登录、广告、分享、录屏、存储、排行、埋点（微信 / 抖音 / 以后 APP 各一份实现）
```

关键点：
- **逻辑和表现彻底分开**。逻辑层是纯 TypeScript，不依赖 Cocos，**同一份代码可以放到服务器云函数里跑**：用来复算赶海成绩、离线塔防结算、校验存档。这是一人开发同时解决“防作弊”和“离线结算”的最省事办法。
- **随机数可复现**：所有随机都用“种子随机数”（给同一个种子，结果完全一样）。服务器发种子，客户端和服务器算出的结果一致，作弊一比就露。
- **时间以服务器为准**：潮汐、员工产出、离线收益都用服务器时间校准，防止改手机时间刷产出。断网时用本地时间暂算，联网后按服务器时间重算。
- **平台适配层**只暴露统一接口（如 `platform.showRewardAd()`），以后上 APP 只换这一层。
- **账号（已定 10-23）**：微信、抖音、APP 都只是入口，共用一套前后端。服务器用**内部玩家 ID**，下面挂各平台身份；未绑定前各自独立，绑定后同一账号、同一存档、同一排名身份。绑定时两边都有进度，让玩家选保留哪一份（建议）。
- **建议目录**：`core/`（钩子、背包、制作、船体、员工、战斗、经济，纯规则）/ `ui/` / `config/` / `data/`（存档与迁移）/ `services/`（云存档、排行、活动）/ `platform/{common,wechat,douyin,app}` / `analytics/`。规则代码只调 `InventoryService.addItem()` 这类服务，不碰平台接口。
- **统一查询**：浮力、重量、剩余承载只由船体服务算，所有界面都问它，不各自累加。

### 3.2 数据与配置
- 数值全在 Excel，按表导成 JSON：物品表、配方表、价格表、浮力重量表、兵种表、弩车表、经验表、箱子掉落表、锁概率表、员工表、建筑表。
- 每张表第一列是唯一 ID，代码里只认 ID，不写死名字。
- 存档带版本号，升级时按版本逐步迁移。

### 3.3 存档与同步
- **本地存档**：主线全部进度，断网可玩；每次关键操作后存。
- **云端备份**：联网时上传压缩后的存档，换手机可找回（按平台账号）。
- **冲突规则**：线上竞争数据以服务器为准；本地独有且合法的单人进度按规则合并，不整份覆盖；校验不过的存档保留但标记，不上榜。
- 存档迁移逐版本走（v1→v2→v3），不靠“缺字段补默认值”；迁移前先备份，失败可恢复。

### 3.4 后端（推荐：一套服务两平台）
| 方案 | 优点 | 缺点 |
|---|---|---|
| 微信云开发 + 抖音云各一套 | 免运维，接入快 | 两套代码两套数据，一人维护累；以后 APP 还得再搭 |
| **云函数 + 云数据库 + Redis（推荐）** | 一套代码服务两平台和以后的 APP；按量计费，量小很便宜；爆量自动扩容 | 要自己备案域名（微信要求请求域名 HTTPS 且备案）；初期多花 2–3 天 |
| 一台轻量云服务器自建 | 最便宜、最可控 | 要自己运维，爆量扛不住 |

**幂等与流水**：所有发金币、发奖励、改物品数量的请求都带唯一请求 ID，服务器只处理一次；物资变化记流水表（谁、何时、为什么、加减多少），查刷子和补偿都靠它。
逻辑数据表（建议）：用户与平台身份、玩家资料、存档快照、物资流水、船体、员工与岛屿、布防、袭击记录、排行与活动、领奖记录、异常记录、配置版本。

首版接口（约 10 个）：登录（各平台 code 换身份）、存档上传/下载、赶海开始（发种子和箱子列表）、赶海提交（上传操作记录，服务器复算）、排行榜读取、野人袭击生成与结算、保护卡状态、快捷聊天、埋点上报、配置版本检查。
排行榜用 Redis 有序集合，省份按 IP 解析一次后存进用户资料。

### 3.5 防作弊（分三档）
- **服务器说了算**：赶海（服务器发箱子、复算成绩）、排行榜、保护卡、野人袭击的生成。
- **服务器抽查**：存档上传时检查合理性（如“每小时最多能赚多少金币”上限、物品数量是否超出可能），异常就不上榜。
- **不管**：纯单机的进度（玩家改了只影响自己，不进榜就无所谓）。

### 3.6 性能
- 包体（官方）：**微信主包 ≤ 4MB、总包 ≤ 30MB；抖音主包 ≤ 4MB、总包 ≤ 20MB**。按抖音的 20MB 做上限，两边都能过。
- 主包只放：启动、出钩、浅海、新手引导；深海、岛、塔防、活动各一个分包，进入前预下载。
- 后端域名要在两平台后台配置**安全域名白名单**，必须 `https://` / `wss://`（抖音官方）。
- 深海 800×800 km、远洋 2500×2500 km 保留为世界设定，**实现上用海域区块 + 航线 + 探索节点**表示，不建连续大地图（低端机和一人开发都扛得住）。
- 图集合批、对象池、同屏 ≤20、不用物理引擎（已定）。目标：首屏 3 秒内可玩（低端机或弱网放宽到 8 秒），低端安卓典型场景稳定 30 帧、高配可开 60 帧，内存 ≤ 300MB（建议目标）。记录首次加载、切场景、内存峰值和真实帧率，只在真机上测。

## 五、四个视角逐项回答

### A. 项目经理

**A1 成功标准（推荐）**：手感闸门——5 人试玩，70% 在 30 秒内学会出钩；教学后首钩命中率 ≥45%，新手前 10 钩成功率 40–60%（太高没挑战，太低劝退）。先用 100–500 名真实测试玩家看行为，再谈日活。小规模测试目标：新手关键流程完成率 ≥ 70%、次日留存 ≥ 25–30%、7 日留存 ≥ 8–10%、人均每日看激励视频 ≥ 2–3 次、人均日时长 ≥ 15 分钟。日活不作为首要成功标准，首月 DAU 1,000–10,000 只是目标情景。
**广告收入估算**：月收入 = 日活 × 每人每日有效展示次数 × 到手每千次收益 ÷ 1000 × 30。到手每千次收益没有公开报价，按低 / 中 / 高三种假设各算一遍，上线后用真实数据替换。结论：只有 1,000 日活时，纯激励视频很难覆盖外包和运营，首版先证明留存。
用户画像：18–35 岁，玩过《Raft》或木筏求生类、塔防类小游戏，通勤和睡前玩。
差异点：“船越造越大、一层层往上叠”的爽感 + 省份排名 + 每晚 8 点赶海。

**A2 范围**：见第四节。新想法一律先进“想法池”。**功能准入三问**：让核心循环更好玩吗？影响哪些已有模块？加入后要拿掉什么？分 P0（上线必需）/ P1（明显提升体验，可推迟）/ P2（扩展或运营），每周只调一次计划。

**A3 进度（推荐）**
| 时间 | 里程碑 |
|---|---|
| 第 0 周（现在） | 定主体、注册微信小游戏账号、定纯中文名字、开始备案和适龄提示设置；软著同步申请（给抖音用） |
| 第 1 周末 | 出钩手感原型，5 人试玩，不好玩就先调手感；同时打出微信、抖音测试包，在目标低端安卓上跑通 |
| 第 2 周末 | 一条完整成长循环：捞 → 背包 → 制作 → 扩船 → 卖商人 → 升级 + 最小新手引导 |
| 第 3 周末 | 主线可玩通（到深海），内测 |
| 第 5 周末 | v1.0 完成，提审微信 |
| 第 6–8 周 | 微信审核与驳回修改（留 2 周缓冲），上线；同时移植抖音 |
| 第 8–9 周 | 抖音提审上线 |
关键路径：出钩手感 → 物品 / 配方 / 存档数据结构 → 浮力重量规则定稿 → 两平台登录、广告、分包验证 → 后端接口 → 提审；手续线独立并行。前四项任何一个延期都会让后面返工。

**A4 成本（估算，需按实际报价）**：软著自己在官网申请免费但慢（约 1–3 个月），加急要花钱；素材包几百到三千元；测试机买 1 台 2–3 年前的低端安卓即可。
服务器按规模（估算）：日活 1 万以内每月几十到两百元；1–10 万加 Redis 缓存和 CDN，每月几百到两千元；10 万以上要换容器集群并有人运维。

**A5 风险表**
| 风险 | 提前信号 | 应对 |
|---|---|---|
| 工期失控 | 第 3 周还没玩通主线 | 立刻砍到第四节 v1.0 以下（先砍塔防兵种和赶海） |
| 手续卡住 | 第 4 周微信备案或资质还没过 | 先发体验版内测；抖音等软著下来再上 |
| 审核驳回 | 名字、概率公示、健康忠告缺失 | 按提审检查表自查 |
| 手感不好玩 | 首钩命中率 < 50% 或首局 < 3 分钟就走 | 放宽判定区、加命中反馈 |
| 刷榜 | 榜首数值离谱 | 服务器复算 + 异常不上榜 |
| 服务器费用 | 爆量 | 按量计费 + 读榜加缓存 |
| 素材版权 | 用了来源不明的图 | 建版权记录表 |

**A6 合规（官方 + 需核实）**
- 微信：发布前必须完成版本审核和小程序备案；企业主体要先做微信认证才能备案（官方）。流程里还有适龄提示设置、中宣部实名认证（官方流程）。纯广告游戏资质审核一般 1–3 个自然日，软著只在名字含英文或“软件”、或涉及品牌合作时才要（官方）。流量主开通条件之一是累计独立访客 > 500（官方），所以刚上线头几天可能还看不了广告。
- 广告接法：小游戏用平台自己的广告接口（微信流量主、抖音流量主），不是接优量汇 / 穿山甲 SDK。
- 防沉迷：用平台自带的实名和防沉迷能力；赶海入口给未成年人显示“今天还能玩 xx 分钟”。
- 抖音（官方）：所有小游戏都要做 **ICP 核准**（拿到核准号才能上架）；没有版号的还要做**小游戏备案**——基本信息和第一个版本审核通过后平台自动申报，备案通过才开放 ICP 核准入口。所以抖音的顺序是：软著 → 基本信息审核 → 版本审核 → 小游戏备案 → ICP 核准 → 上架，要预留时间。首次上线 QA 回归约 1–3 个工作日，且会回归多个宿主 App。名字不能有英文。
- 抖音：必须接防沉迷；游戏开始前要显示《健康游戏忠告》和著作权登记号；游戏名必须和软著完全一致（官方自审标准）。抖音小游戏没有 banner 广告，有激励视频和插屏。
- 版号：业内普遍做法是纯广告无内购的小游戏不需要版号，但个别地方有处罚案例，且企业主体是否要版号说法不一，**需以平台客服最新答复为准**。内购一定要版号。
- 隐私政策要写：收集了哪些信息（平台身份、IP 推算省份、设备信息、广告收集的内容）、用途、保存多久、怎么删除；要明写“通过 IP 判断省份，只用于省份排名”。微信 MP 后台还要单独配置隐私保护指引。
- IP 判断省份会有误差（VPN、校园网、出差），省份榜规则写明“以首次登录省份为准，每月可改 1 次”（建议），减少争议。备选：直接让玩家首次进入时自己选省份（省掉位置推断的解释，但可能乱选）——属于实现方式，不改“省份排名”这个已定设计。
- 分享：不能强制分享换奖励，不能把分享当成游玩门槛。拉新优先抖音录屏高光（出钩命中、开金锁、守岛回放），微信侧分享省份战报，只展示不给奖励。
- 隐私政策还要写：用户怎么查阅、更正、删除信息，怎么注销账号；未成年人信息怎么处理。

**A7 运营**：广告收入粗估 = 日活 × 人均激励视频次数 × 每千次收益 ÷ 1000 × 分成，先按日活 1 万、人均 3 次估一个区间再看实际数据。拉新：抖音录屏（造了个超大的船、守岛成功的回放）最有效；微信靠分享卡片和好友排行。更新节奏：上线后每 1–2 周一个小更新。

**单点风险**：一个人生病或断网就全停——每周末把工程推到能运行、能出包的状态。

**A8 验收标准（推荐）**：无崩溃会话 ≥ 99.5%；低端机首屏 ≤ 5 秒（弱网 ≤ 8 秒）；连续玩 30 分钟不卡、不明显发烫；新手引导完成率 ≥ 70%。另外逐项过：强退 / 切后台 / 断网重连不丢档不重复领奖；老存档能迁移；广告失败或不看广告游戏照常；篡改本地分数、重复提交、重放领奖都拿不到成绩或奖励；活动跨 21:00 的处理；能找到隐私政策、注销说明和投诉入口。每次提审前跑一遍全清单，不只测新功能。
**测试机型**：4GB 内存低端安卓、中档安卓、刘海屏 iPhone、超长屏手机、老系统版本各 1 台（可借），微信和抖音真机宿主都要测。

**B2 问题回答**
- **好玩节奏**：第 1 分钟——出钩命中的手感；第 10 分钟——第一次扩船、造出新工具；第 1 天——驶出浅海前的冲刺、第一次赶海；第 7 天——船已经叠到好几层、占到第一座岛、开始守岛。
- **每日节奏（推荐）**：上线收离线产出 → 潮汐（每 6 小时）捞一波 → 晚 8 点赶海 → 睡前布防。一次打开 5–15 分钟。离线收益最多累计 8 小时（建议），逼玩家一天回来 2–3 次。
- **失败代价**：超重 = 不能再建、不能再装（不沉船）；岛被攻破 = 野人只抢普通生活物资（已定），有保护期。不做“全没了”。
- **承载提示（建议）**：重量 / 浮力 ≤ 80% 正常；80–100% 黄色警告；到 100% 禁止再建再装（即已定规则）。界面能看到浮力总量、重量总量、剩余承载和“最重的是哪几样”。数值一律用整数。
- **出钩配置**：蓄力时长、有效命中区、各物体命中半径、失败反馈分成独立配置项，方便按埋点调。“无擦钩”写成明确判定：钩点与物体中心距离 ≤ 命中半径才算中，否则就是没中。
- **经济**：金币来源 = 卖给商人、赶海、任务；去处 = 赶海票、买图纸、雇员工、扩建。每天产出略大于消耗，后期靠高价物品（金锁箱、深海材料）拉开差距。
- **浮力/重量起步值（建议）**：初始筏浮力 100、空筏自重 40，留 60 给前期建造（新手阶段浮力余量至少是建筑重量的 1.2 倍，前 30 分钟不能卡人）；第一个房间框架重 20、房间内设施 5–15；货物每格按物品重量。目标是前 30 分钟每扩一次船能多盖 1–2 个房间。
- **赶海票公式（建议）**：票价 = 所带装备档位的期望收益 × 35%，取整到 50，夹在 200–2000。装备越好，期望收益越高，票越贵，但始终能赚回来。装备参考价一律读配置表。上线前用模拟玩家（几百到上万人的装备分布）跑一遍，看高低装备玩家的收支。
- **要知道的风险**：已定按“打捞总价值”排名，票价只能拉平收益率，**拉不平名次**，高装备玩家一定占优。这是已定规则的代价，不改；可选的缓解是在结算页额外显示“同装备档位内排名”（只展示，不另设奖励）。
- **品阶与掉落**：品阶按原价落档（已定），是单向的“价格 → 品阶”，不循环。要守住的是：掉落概率单独配表，不反过来用品阶改价格；改价格时检查品阶会不会跟着跳档。
- **无限出钩的经济**：不限次数（已定），所以每次出钩的时间成本和平均收益要算清，确认不存在“几乎零成本刷金币”的循环；离线产出有上限（建议 8 小时），每次上线只结算一次。
- **未成年人**：防沉迷限制下他们只能在周五、六、日和节假日 20:00–21:00 玩，正好覆盖赶海时间；工作日进不来，不另做补偿。
- **断网冲突**：以服务器时间为准重算离线产出；野人袭击由服务器生成，联网后结算。
- **账号互通（已定 10-23）**：未绑定不互通；绑定微信和抖音后即同一账号。首版就要把内部玩家 ID 和平台身份映射做进后端，绑定界面可以放 v1.1。
- **区服**：首版不分区（拍板 5）。
- **聊天**：首版快捷短语 + 表情。
- **看哪些数据**：次日/7 日留存、新手每一步流失、首钩命中率、首局时长、首日扩建次数、人均看广告次数、赶海参与率。

**C1 推荐**

- 设计稿：竖屏 750×1334 为基准，适配刘海屏安全区和 20:9 长屏；平板按宽度留边。

- 力度条三重提示：颜色 + 刻度 + 命中瞬间的数字 / 震屏。

- 关键反馈最低要求：出钩（蓄力、力度窗、抛物线、中 / 没中）、拾取（飞入背包、数量跳动、稀有强调）、开箱、建造（合法 / 非法预览）、加层（层轮廓 + 浮力重量同步变）、升级、守岛结算（摘要、损失、原因、回放入口）。
- 45° 俯视 + 多层：先定格子坐标、层与层的遮挡显示（上层半透明或切层查看）、设施能放哪，否则建造、渲染、存档会各用一套坐标。

- 字体：用免费可商用中文字体（如思源黑体、阿里巴巴普惠体），最小字号 24px（750 宽设计稿下）。
- 美术来源：一套风格统一的素材包打底 + AI 生成补充（必须人工统一描边和配色）+ 版权记录。素材包一定看清是否允许商业使用；外包按图计费是兜底（成本高，要签著作权转让）。
- 资源量估算：物品图标、船体地块、员工、野人、全套界面，加起来几百个，必须先列资源清单再动手。

- 塔防寻路：从大门做一次反向广度搜索，得到每一格“往哪走离大门最近”（流场），多入口共用一张图，玩家改地形时重算一次即可；结算用固定步长逐帧模拟，**回放不存画面，只存“种子 + 布防 + 来袭波次”，回放时重新模拟一遍**，几 KB 就够。
- 船体：用三维格子（x, y, 层）存房间；第 n 层的格子下面必须有第 n−1 层的房间；浮力和重量在每次建造/拆除时增量更新，不必每帧算。

- 平台接口建议拆成：登录、广告、分享、存储、排行、支付（APP 预留）、数据分析、**抖音录屏**；业务层只调接口，构建时按平台注入。
- 存档加校验和（防误损坏，不当防作弊）；回放存事件流（单位、路径节点、时间、结果），每场约 2KB，只留最近几场。
- 埋点和崩溃：先用平台自带的数据分析 + 自己的埋点接口，不接第三方，省包体。埋点只回答三件事：玩家在哪停下、哪里卡住、什么让他回来。重点：首钩耗时、命中率、引导每步进出、第一次制作 / 扩建 / 升级、背包满、超重提示、员工缺食、守岛失败、广告点击与**实际看完**、存档冲突、接口失败。用户标识去标识化，只留必要字段。
- 爆量降级顺序：先保账号和存档，再限排行刷新、快捷聊天和非必要统计。

## 五点五、数值与规则风险（不改已定规则，只提醒要验证）

| # | 风险 | 说明 | 建议做法（都不改已定规则） |
|---|---|---|---|
| 1 | 开锁成本可能大于箱子收益 | 已定：连续命中、失误归零、蓄力就断一根；命中区 20/15/10/5%。命中区比例≠命中率（玩家是看准时机松手），但金锁要连中 4 次，命中率一低成本就爆。连中 n 次的期望尝试次数 = (1−pⁿ) ÷ ((1−p)·pⁿ)，p 为单次命中率。例：p=0.6 开金锁约 17 根 ≈ 20 万金币；p=0.8 约 7 根 ≈ 8.6 万 | 第 1 周原型里实测各档命中率；用暂定的工具价格（300/2000/12000）当调节旋钮，保证“期望开锁成本 < 箱子期望价值”。另：高级工具每区服每天 3 个，日活上千时几乎人人买不到，金锁箱会长期囤着——已定，上线后看数据 |
| 2 | 总收益榜接近“在线时长榜” | 已定“每收获一件都算”+ 出钩不限次数，在线越久分越高 | 规则不改；服务器按“每小时理论最大收益”设上限校验，超了标记复核 |
| 3 | 称号 +25% 在人少时变成人人有 | 9 兵种 × 每省前 10 = 每省 90 个称号；首月每省可能只有几十到几百人 | 规则不改；上线前用模拟人数验证塔防难度；作为第一个要看数据的平衡点 |
| 4 | 浅海“救第一个员工”没有来源 | 等级表 6–10 级救第一个员工，但浅海没写员工从哪来（野人 20 级才出现） | 【建议】浅海漂流物里加“漂流遇难者”，作为员工来源，不改等级表 |
| 5 | 净浮力怎么算没写清 | 已定“材料本身也占容量” | 【建议】写成：剩余承载 = Σ材料容量 − Σ材料自重 − Σ(建筑+货物+员工重量)，≥0 才能建 / 装 |
| 6 | 激励视频没有挂靠点 | 已定只做“再来一次 / 双倍”，但出钩不限次数，没有“一次” | 【建议】挂到：离线 / 员工产出翻倍、潮汐延长、开锁失败补一根工具（每日上限）、赶海结算双倍展示等，具体位置进广告位设计 |
| 7 | 玩家航速没定 | 深海 800×800 km，野人 100 km/h；玩家若同速，跨图要十几个小时 | 【建议】定玩家航速，或用航线节点缩短；挂机导航已定可用 |
| 8 | 沉船信息“本区服 100 份 / 天” | 同时写着“按玩家各自结算”，不清楚是全区服共 100 份还是每人 | 待用户澄清；若是全区服共享，日活上千时会严重不够 |
| 9 | 占岛算不算“主动进攻” | 首版抢野人船算主动进攻、会让保护卡失效；占岛没写 | 【建议】占岛不算主动进攻 |
| 10 | 潮汐“漂浮物多” vs 同屏 ≤20 | 上限 20 时“多”无法用数量表现 | 潮汐时用刷新更快、好东西比例更高来表现 |
| 11 | 低画质偶遇沉船“不显眼” | 小屏上不显眼≈看不见 | 【建议】靠近时加水花音效或轻微闪光（不是声呐） |

## 六、建议重新考虑的已定设定

1. **“9 个兵种全做”（首版）**：塔防是首版最重的系统，9 个兵种的美术、数值、平衡测试一人 5 周做不完。建议首版 3 个，v1.1 补齐（拍板 3）。
2. **“总收益榜”**：本地存档算出来的总收益可被改，建议只保留服务器能算的榜（拍板 4）。
3. **“区服聊天 + 跨区世界频道”（首版）**：自由聊天要内容审核和未成年人保护，个人主体可能开不了；建议首版快捷短语。
4. **首版排期 5 周含提审**：手续流程官方预计 13–37 个工作日，建议排期写成“开发 5 周 + 审核缓冲 2 周”，手续从现在开始并行。
